# 给硬件开发者：进化与五种动作的统一口径

依据：Eric 在本轮对话中的最新修正，以及已核对的飞书产品文档修订 204、仓库 `53a4f95`。本页是产品修正与接入交接，不是五种新动作已经完成的软件或实机验收记录。与旧快照中的“转头”候选冲突时，以本页的新决定为准；不要手改飞书快照冒充上游更新。

## 先了解新增的进化逻辑

- 形态树：小牛 → 普通牛来；然后分为骚牛 → 仙牛、硬牛 → 暗黑牛。
- 点击左侧形态直接选择，并进入手动模式，可以跨分支。切路线按钮只浏览路线，不切形态。
- 自动模式默认每 **5 轮完整对话**调用一次独立的进化评估 LLM，读取本次培养全部已完成对话，决定保持或沿合法直接后继前进一步。满 5 轮不是必定升级。
- 左下角设置可改轮数、评估模型和 API 网关。网页已有状态机与接口；真实评估模型/网关仍需配置。不能把任意聊天 API URL 直接当作本项目网关。
- 重置回小牛，清空本次培养会话和计数，作废在途评估与旧版本回应；保留设置。云端观察区的旧设备日志不是培养历史，不能再次计轮。终点不会自行重开。
- 形态切换通过 `profile.update` 递增版本，本机实际应用提示词后返回 `profile.applied`；等待确认时不能让新形态借旧提示词执行动作。重置的停止请求也必须等待设备回执，网页不能代替本地停止。

完整网关格式和计轮边界见 [进化运行合同](evolution-runtime.md)。现有实时路径按 `commandId` 关联输入、回复、动作与 `command.result`，只计非模拟、版本一致、满足完成条件的交互；流式片段、示例播放、重复事件和过期回应不计轮。小牛无声动作也应按该合同明确接入，不能靠播放动画推断一轮完成。

三个模型职责分开：**JEV 选动作，角色 LLM 生成语言，进化评估 LLM 判断形态是否变化。** 六个形态不是六个必须单独训练的 JEV 模型；形态切换改变提示词、人格和软件表现，不自动增加机械臂能力。

## 五种基础回应动作

按 Eric 最新修正，删除“郑重批准”，好奇歪头仍分左右两个，共五种。以下含义在所有牛来形态、其他角色模型中保持一致；模型骨骼不同可以适配实现，人格可以影响选择偏好和同义动画变体。

| 产品动作 | 含义与动作约束 | 建议统一 ID（待协议实现） |
| --- | --- | --- |
| 确认点头 | 一次清楚的点头，表示听到、理解或确认。不能随机替换为双点头。 | `NOD` |
| 摇头 | 完整的往复摇头，表示否定或不同意；不是向一侧转头后停住。 | `SHAKE` |
| 得意双点头 | 两次有节奏的点头，表达得意；保留两次的结构，不随机退回单点头。 | `NOD_DOUBLE` |
| 左侧好奇歪头 | 向角色自身左侧倾斜，表达好奇；结束按该动作配置恢复。 | `TILT_LEFT` |
| 右侧好奇歪头 | 向角色自身右侧倾斜，表达好奇；结束按该动作配置恢复。 | `TILT_RIGHT` |

左右统一采用**角色/硬件自身视角**，不是摄像头镜像或观看者左右。接入者应在各模型坐标与设备坐标之间显式映射；不能直接照抄网页正负角度给舵机。

**删除“转头看向”这类离散回应动作。** `LOOK`、左转头、右转头、回望不作为上述动作池候选；摇头不能通过随机选“向左看/向右看”替代。`WAIT` 是不执行动作的控制结果，Stop 是停止指令，都不占五个动作名额。网页其他场景里的挥手也不自动成为这套机械臂回应库的动作。

这里收紧的是 JEV 可选的回应动作；摄像头连续人物跟随属于独立感知/控制闭环，不能混入随机动作池。网页鼠标跟随也不能当作 JEV 或机械臂动作已经执行的证据。

## 每个形态遵守同一条执行链

1. 锁定本轮输入、形态和提示词版本；JEV 只从当前设备已支持的候选中选择一个五种动作 ID，不能执行时返回 `WAIT`。
2. 同一回应分别交给机械臂适配器和网页动画选择器。机械臂执行经过验证的预设，网页从“当前形态 + 同一动作 ID + 已加载骨骼/资源”的候选中随机选一个。
3. 随机只改变同一动作的表现风格，不改变确认/否定/得意/好奇的含义、单/双点头结构或左右方向。没有同义资源就显示动画未就绪或保持 idle，不借另一种动作冒充。
4. 硬件与动画分别记录执行状态。网页播完不等于机械臂完成；本机回执不能由模型台词或请求已发送替代。
5. 同一事件只执行一次。切形态、重置、断线后的旧指令不重放；不能让旧回应修改新形态或新培养会话。

例如，骚牛选“左侧好奇歪头”可以比小牛更俏皮，暗黑牛可以更克制，但三者都必须向各自左侧歪头。进化改变人格和表现，不把同一个动作 ID 在另一形态解释成“向右看”。

## 代码一致性核对：目前仍有差距

| 位置 | 已核对的现状 | 与新定义的差距 |
| --- | --- | --- |
| `shared/live-protocol.mjs` | 允许 `NOD / LOOK / TILT / WAVE / WAIT` | 缺少独立摇头、双点头和左右歪头 ID；还保留 LOOK/WAVE。上表新 ID 目前不能直接发给线上服务。 |
| 默认动画映射 | NOD 随机单/双点头；TILT 随机左/右歪头 | 必须按五种动作拆开，方向和单/双点头结构不能随机变化。 |
| 配置校验与动画选择 | 校验动画名属于全局白名单；保存每形态配置 | 尚未强制动画与动作语义一致；也没有六套已验收的独立形态动画资产。不能仅凭下拉框有形态就说六模型已适配。 |
| `src/live/animation.mjs` | 点头、双点头、左右看、左右歪头程序动画 | 缺少往复摇头；左右看不符合本次动作库。 |
| 设备套件 | 可替换 JEV/执行/语言适配器；默认模拟 | 需要同步动作白名单与配置版本。默认模拟不证明五种机械动作可执行。 |
| 飞书快照 §5.2.4 与 §3.1 | 前者仍有转头候选，且点头/歪头关节表与后者的当前控制记录冲突 | 本页覆盖新动作语义；真实轴、方向、幅度、时序以接入者实际控制器和逐项验收为准，不能按旧表猜测。 |
| 进化 | 手动切换、设置、重置与评估请求已实现 | 真实评估模型/网关待配置；原 README 中“自动进化尚未定义/固定关闭”已过时。 |

本轮先统一产品口径和交接；尚未修改线上动作协议或控制机械臂。实施时需一起更新 Worker 白名单、网页映射/预览、本机适配器与既有房间配置；不能只改按钮名称。旧房间的 LOOK/TILT 配置必须显式迁移并递增提示词版本，再由设备确认，不能静默把旧 TILT 猜成某一个方向。

验收应逐形态覆盖五动作：摇头往复、单/双点头可区分、左右方向固定、无转头候选、随机不跨语义、资源缺失不冒充成功、真实回执与重复/过期事件处理。硬件不支持某动作时先禁用并说明，不能用相反动作填空。

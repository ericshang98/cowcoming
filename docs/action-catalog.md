# 桌面宠物动作目录

牛来的动作现在分成两层：

- **行为目录**描述桌面宠物想表达什么。GEV/JEV 从这里选择语义动作，网页可以在没有硬件时先完整演示。
- **设备能力**描述某一台机器人实际能执行什么。设备通过 `supportedActions` 声明已经验证的动作；未声明的动作不会下发到实机。

这让同一套软件可以服务不同的桌面宠物。五个旧 ID（`NOD`、`SHAKE`、`NOD_DOUBLE`、`TILT_LEFT`、`TILT_RIGHT`）仍然兼容 BenBen，但它们只是一个硬件 profile，不是公共动作上限。目录保留 32 个协议 ID，其中 29 个是桌面宠物选择器的独立动作；`NOD_DOUBLE`、`BOW`、`BELLY_BREATHE` 只为旧房间兼容而保留，不在新 UI 中重复展示。

## 目录

| 身体区域 | 动作 |
| --- | --- |
| 头部与视线 | 确认点头、摇头、左右好奇歪头、看向左右、抬头、低头 |
| 躯干与身体 | 伸展、身体呼吸、抖一抖、身体转向左右 |
| 脚与前肢 | 左右脚轻点、前肢挥手、伸出前肢、交叉前肢 |
| 肚子与呼吸 | 摸摸肚子、捂肚子笑 |
| 尾巴与姿态 | 摇尾巴、坐下、站起、休息、醒来伸懒腰 |
| 组合表达 | 开心蹦一下、庆祝摆动、害羞躲一下、靠近安慰 |

当前六套牛来模型用已有的骨骼动画和软件动作来演示目录动作。动作目录的语义、身体区域和组合关系已经是稳定接口；动作必须找到同名的已登记 clip 或匹配的程序化骨骼动作，否则播放器会显示资源不可用。播放器不会再用点头、鞠躬或挥手冒充另一个动作。

## 给新机器人接入

设备端只需在状态消息里声明自己真正验证过的能力：

```json
{
  "type": "device.status",
  "actionContractVersion": 2,
  "hardware": "ready",
  "supportedActions": ["NOD", "PAW_WAVE", "TAIL_WAG", "WAIT"]
}
```

动作执行仍然使用语义 ID：

```json
{
  "type": "action.request",
  "actionId": "PAW_WAVE",
  "eventId": "turn-42-paw-wave"
}
```

设备适配器负责把 `PAW_WAVE` 映射到自己的舵机、灯光或其他执行器。网页和 GEV 不读取也不生成舵机角度；限位、互斥、停止、回执和安全策略留在本机适配器。

推荐为每个动作记录：

- 所占身体区域和互斥区域；
- 进入姿态、退出姿态、时长和是否可中断；
- 需要的执行器 / 传感器；
- 已验证的设备、固件和安全边界；
- 软件预览 clip 与硬件执行 ID 的映射。

扩展目录时先在 `shared/action-catalog.mjs` 增加语义定义，再为各形态登记软件变体；不要把某一台机器的关节编号写进公共目录。BenBen 的旧五动作 profile 可以继续工作，新的机器人可以声明完全不同的子集。

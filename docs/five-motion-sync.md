# 本机五种回应与网页同步

用户已确认本轮只同步网页已有五种回应，不扩展网页的转头、转身、站坐、复位动画。沿用动作合同 2 和人格版本 `niulai-six-v1-6194348364b6`，网页与 Worker 的五种 ID 不变。

| 本机动作 ID | 网页动作 ID | 表现要求 |
| --- | --- | --- |
| nod | NOD | 一次点头 |
| shake_head | SHAKE | 往复摇头 |
| nod_double | NOD_DOUBLE | 两次点头，不随机替换为一次 |
| tilt_left | TILT_LEFT | 角色自身左侧歪头 |
| tilt_right | TILT_RIGHT | 角色自身右侧歪头 |

原本机只有单点头，新增 `nod_double` 独立候选：复用 nod 的 3 号示教位置 1359→1598 两遍，时序 1.5/1.2/1.5/1.2 秒，再以原 1 秒返回统一默认姿态，总计 6.4 秒。不改变原动作的速度、加速度、扭矩或限位。正常结束继续持位，取消和故障仍由原执行器处理。动作库因此为原 11 个动作＋双点头＋独立复位，共 13 个候选；授权开放不表示实机已验收到位。

明确的“点两次头／点头两下／双点头”只给 JEV 双点头候选；单点头和左右歪头也分别保持语义。否定或能力不可用时不替换为其他动作。

桥接不调用第二个 JEV，不连接串口。只在本地执行器已发布 moving/simulated 后发送同轮决策和动作事件。控制器通过 `projectable_motions` 声明本机具备的候选；桥接从该声明构造 supportedActions，与房间 allowedActions 取交集投影。连接旧控制器时仍退回 NOD-only，不虚报新增能力。房间动画设置不再削掉本地其他已授权动作；未映射或未在房间开放的动作只写日志，不套用别的动画。

已接受的网页动画继续完整播放；重复事件、旧形态回执和断线重连不重播。正常机械指令结束仍报 sent，网页播放完成不等于实际机械到位。

- 本机 339 项 Python 回归、28 项 JS 回归通过；双点头用假总线验证两次轨迹、固定时序、默认姿态和持续持位。
- 五个固定测试句由真实 JEV 在五个候选中逐项选对。仅发送通用动作标签和固定文本，不发送人格、历史、录音或电机参数。结果见 [JEV 检查](verification/five-motion-jev.json)。
- 隔离 Worker＋实际控制器/桥接代码＋Chrome：六形态 × 五动作共 30 个组合通过，另外覆盖去重、停止、断线重连、同轮单次决策、人格确认和未接入网页命令的明确拒绝。完整 [矩阵记录](verification/five-motion-bridge.json)。模型/语音/电机为测试替身，不能作为整机实测证明。测试工具按真实网页保留 GLTF 原名骨骼别名，解决普通牛双点头在测试环境中被误判未加载的问题。

## 发布与启用

原 Worker 已支持全部五个 ID，无需为这次映射重新发布 Worker。网页所有者继续发布上一轮六形态资源；本次网页修改为联调检查与交接记录。实际映射变化在 benben 控制器与桥接，两者都需使用本轮版本。只有更新 GitHub 源码、没有激活现场服务时，现场仍保留旧的映射范围。

本轮不自动停止或重启承重服务。现场启用应结束收音并持位，确认机械可靠支撑后切换控制器和桥接；检查原房间 profile revision 与 appliedRevision 一致、supportedActions 包含五种动作和 WAIT。再用“点一下头／摇摇头／点两次头／向左歪头／向右歪头”逐项实测，正常收尾使用“结束收音并持位”。网页动作帧和机械指令节奏不要求逐帧相同。

# 角色模型存储与接入

依据：Eric 本次明确要求，以及[飞书产品文档 §3.2、§3.3.5](https://uxl9fceo481.feishu.cn/wiki/Ehc9w5bs1ic2gEkwZjCc8Eo1nmb#doxcnLZgggwA6qhtA1J4jNlHsJf)。这是角色视觉／3D 模型的资源规则；JEV、LLM 等推理模型的部署另行定义。

## 已确认的存储规则

| 对象 | 现阶段存储方式 | 用户使用方式 |
| --- | --- | --- |
| 其他 IP 的角色模型 | 上传云端服务器，提供网站可加载的模型资源 | 用户切换不同 IP、预览对应模型，不需要各自准备本地文件夹 |
| 牛来的多个进化形态模型 | 先以本地文件夹形式管理，各形态分别关联文件 | 在同一个牛来 IP 内切换或按进化规则进入不同形态，加载对应模型 |

牛来是具有进化树的一个 IP，会有多个形态模型；每个形态不是一个新 IP。这里的本地文件夹决定针对牛来，不是奶龙。奶龙等其他 IP 按云端模型方案接入。

## 开发时怎样区分

`ip_id` 标识角色；`form_id` 标识该角色的形态；`model_asset_id` 关联具体资源。切换其他 IP 与牛来内部的形态转换分别记录，预览其他 IP 不推进牛来的进化。角色资源状态与逻辑形态、硬件执行状态分别显示。

其他 IP 的模型在云端上传并验证可加载后，才能标为可用。开发时登记资源地址、版本及关联 IP，处理加载中、资源缺失和加载失败；预览成功不等于硬件已切换或执行完成。具体云端服务与上传入口尚待接入，不在本次文档更新中指定供应商。

牛来的模型先按本地根目录与各形态的相对路径登记。下面仅是建议目录，实际根目录、文件名和已有素材须核验；不要创建空文件冒充已经收到模型：

```text
<本地模型根目录>/niulai/
  <form_id>/
    <模型文件>
    <该模型依赖的贴图等资源>
```

换电脑时，Git 中的配置与文档可以同步，本地模型文件夹不会仅因 `git pull` 自动出现；需要在目标电脑准备同一批资源并配置根目录。未提供或无法读取某个形态的模型时，应明确显示资源缺失或参考模型，不冒充目标形态的正式外观。

“本地文件夹”是当前的资源管理方式，不代表云端网页已经能够读取任意磁盘路径。授权选取、导入或经本机程序读取的实际接入方式需要单独实现和验证。现有随网站发布的参考 GLB 只是当前展示资产，不代表牛来的全部形态模型已完成云端迁移。

## 本次交付边界

本次更新开发约定与飞书文档，未上传其他 IP 模型、未迁移牛来模型，也未实现新的文件读取或切换功能。后续 Agent 按本规则接入实际资源，并分别记录资源齐备、加载成功和交互验收结果。

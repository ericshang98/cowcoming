## 为什么暂不启用自动评估

交接包只有分支状态机和评估 HTTP 合同，没有真实评估服务。当前自动计轮只识别网页发起、带 commandId 的完整交互，并要求动作完成回执；Benben 自主麦克风回合尚不纳入。其 timed 动作的 sent 只证明指令已播放，不能改名 completed 来凑进化轮数。人格切换在本地会话开启时也需要排队。

因此本次保留手动选择，不增加新模型、记忆库、积分或额外评估服务；不会满五轮就直接升级，也不会假装自动进化已经打通。

若后续要自动化，最小方案是复用豆包和现有分支状态机：本地记录有效完成的对话，每五轮在回应结束后后台判断一次，返回 stay 或允许的下一形态；失败保持原形态，不阻塞当前说话。沿用版本回执确认实际切换。先补齐自主语音回合关联和空闲时同步，再启用这条路径；不以机械位置到位作为“对话结束”的替代证据。

分支保持：小牛 → 普通牛来 → 骚牛 → 仙牛，或普通牛来 → 硬牛 → 暗黑牛。重置、手动选择、迟到结果作废等已有规则保留。未配置 endpoint/model 时不会发送评估请求。

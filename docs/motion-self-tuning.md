# 自己调动作，再交给设备开发者

依据 Eric 2026-09-24 当前要求：先自己调整，再交给朋友接设备接口。沿用飞书快照修订 212 / 动作合同 2 的五种语义。此页记录代码的实际行为，不改写上游快照。

## 打开

准备 Node 24，执行 `npm ci`。首次准备 Python：

```sh
python3 -m venv .pwc/motion-python
.pwc/motion-python/bin/pip install -r examples/device/requirements.txt
npm run motion:lab
```

终端出现启动成功后，打开 <http://127.0.0.1:4337/__motion-lab/start>。Mac 也可双击 `scripts/motion-lab.command`。终端要保持运行；Ctrl+C 停止本次启动的网页、临时 Worker 和 Python 模拟器。不会重启、安装或覆盖已有设备程序，也不占用默认开发端口。

该入口只绑定本机回环地址，自动创建本地测试房间、填入本次浏览器连接信息。仍经过正常的房间绑定、电脑在线和配置确认流程。密钥留在忽略的 `.pwc/motion-lab` 中，不写入网址、配置导出、Git 或生产构建。每次启动创建新测试房间；浏览器中的动作参数按固定网页地址独立保留。临时 Worker 房间数据不是交付物。

## 怎么调

1. 左侧选择小牛、普通牛来、硬牛、仙牛或暗黑牛；骚牛显示待补模型。
2. 点击五个动作之一试播：确认点头、摇头、得意双点头、左侧好奇歪头、右侧好奇歪头。
3. 改速度（0.5–1.5 倍）和幅度（50%–125%），再点同一动作重播。左右以角色自身为准。
4. 参数按“形态＋动作”分别保存，刷新仍保留。播放过程中锁定本次参数；下次动作才使用修改后的值。停止会中断当前播放并恢复待机。
5. “恢复当前动作默认值”只恢复选中的一项；“导出全部参数”下载五形态共 25 项配置。导入成功会一次性替换 25 项，导入前可先导出备份。格式、模型 SHA、动作合同或参数范围不符时整份拒绝，保留原设置。

本机浏览器存储可能被清理，因此定稿后请导出备份。另一个浏览器、设备、端口或正式网站不会自动得到这些参数；打开动作调试并导入同一文件即可应用。参数不会上传云端，不改原始 GLB。实际播放将每条旋转轨道相对首帧中立姿态缩放，位置和缩放轨道保持原值，动作方向和单/双次语义不变。已经验证的模型版本与导出文件绑定。

正常 WORK 页也保留“动作调试 · 仅软件”入口，在左侧进化路径下方；仍需绑定设备且电脑进程在线。调试入口仅换成紧凑形态选择器，其他 IP 与进化树逻辑不变。

## 交给朋友什么

- 你调好的 `cowcoming-motion-tuning.json`，以及对应版本的网页代码和模型。
- [硬件开发交接](hardware-handoff.md)、[设备接入说明](live-device.md)与仓库导出的 `public/downloads/cowcoming-device.tar.gz`。
- 若朋友需要在网页复现：运行同版本网站，导入你的 JSON；播放器对手动预览和设备决策触发的网页动画统一应用参数。

JSON 标记 `scope: software-only`，不能直接换算成舵机角度、力度或硬件速度。真实硬件由朋友在适配器里按相同五个动作 ID 标定行程和执行结果；网页动画与设备动作各有完成回执。

本地 ExampleAdapter 的文字回复、JEV 决策和设备动作均为示例模拟。修改提示词可以检查同步流程，但不会让示例模拟器成为真正的 JEV/LLM。没有真实摄像头、模型推理或机械臂验收结果。

## 验证入口

- `npm test`：参数校验、错误存储、相对旋转、真实播放完成时机、停止与资源释放，及现有项目回归。
- `npm run build`：正式构建不包含本地登录引导。
- 启动 `npm run motion:lab` 后执行 `node scripts/motion-tuning-qa.mjs`：25 个实际 GLB 动作、模拟设备驱动的调参播放、刷新保存、导入导出、坏文件拒绝、恢复默认、停止与手机无横向溢出。

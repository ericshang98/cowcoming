一句话定位

Cowcoming：基于JEV决策模型的可进化AI宠物。



# 1. 产品定位

**Cowcoming 是基于 JEV 决策模型的可进化 AI 宠物系统。**项目提供可承载不同 IP 的感知、结构化决策、语言表达、行为调度、成长与形态解锁、硬件控制能力。JEV 连接现场状态与允许的行为，LLM 负责符合角色形态的语言；“牛来”是当前展示 IP。系统、IP 内容与具体硬件展示分别设计。

**产品价值：**让不同 IP 能够通过同一套系统感知环境、及时回应用户，并用各自的行为与成长形态呈现连续的互动体验。当前以机械臂桌面宠物原型验证这套链路；通用能力与具体 IP 内容分别设计和维护。

## 1.1 系统、IP 与展示的边界

| 层次 | 负责的内容 | 与牛来的关系 |
|-|-|-|
| 通用软硬件系统 | 感知接口、场景状态、JEV 决策接口、行为执行与调度、成长进度、硬件适配和执行反馈。 | 承载牛来及其他 IP 的共同能力。具体接口设计仍待实现与验证。 |
| IP 内容与配置 | 角色名称与设定、形态与成长路线、互动规则、动作与反馈素材、模型判断标准及候选行为。 | 牛来拥有自己的一套内容与配置；其他 IP 可定义不同表现和成长路线。 |
| 展示实例 | 选定的 IP、实际硬件、现场演示流程及这次开放的能力。 | 牛来结合当前机械臂和随头摄像头，展示系统的一部分能力；展示范围单独确定。 |

**三个独立维度：**IP 表示角色是谁；形态是该 IP 进化树中的节点，绑定角色视觉／3D 模型及表达配置；硬件载体表示用什么设备呈现。牛来的树已确定为小牛 → 普通牛来，再分为骚牛 → 仙牛、硬牛 → 暗黑牛，详见 5.2。其他 IP 可以定义自己的模型与分支，不复用牛来的节点名称充当通用等级。

# 2. 当前已确认的产品方向

**当前展示原型的硬件形态。**本轮用机械臂作为载体，头部可以转动，外部套上头套，以头部和机械臂的预设动作表达反应。摄像头安装在末端，随头部视线一起转动。该硬件用于牛来 IP 的展示验证；灯光、屏幕、扬声器等附加反馈设备尚未确认。其他硬件的适配属于可扩展方向，不能视为已经支持。

**视觉能力。**目标体验是人物检测与视觉跟随，每轮关注一位确认的参与者：通过互动位置与前端选中框确认，无法确定时由现场人员选择，旁人进入不自动抢占；短暂遮挡等待，目标无法恢复时暂停。当前网站的鼠标跟随只属于网页角色交互，不等同实机摄像头跟踪。人物身份、手势与姿态识别按实际模块能力分别验证；称呼偏好由用户自选，不凭外观推断身份或决定进化路线。

**交互方式。**产品同时支持主动交互和被动交互。主动交互由系统按时间或现场状态刷新后触发判断；被动交互由用户说话或发送消息触发。

**首版分工与表达约束。**不同阶段使用不同提示词，JEV 从少量允许的基础动作中选择一个；机械臂执行对应基础动作，已绑定的 WORK 页面从提前规划、匹配该基础动作和当前阶段的软件动画中随机选一个呈现。软件角色以骨骼动画表达丰富变化，机械臂不因此增加动作能力。LLM 独立提供符合阶段的语言，小牛以无声动作和少量短音节为主。代码中的观察区目前是预设示例，真实模型流与双端联动链路仍须单独核对和接入。

# 3. 模块化系统架构

| 模块 | 职责 | 主要输入 | 主要输出 |
|-|-|-|-|
| 视觉感知 | 检测周围的人并维护人物跟踪状态 | 摄像头画面、设备位置、历史跟踪状态 | 目标数量、目标位置、距离、跟踪稳定性等状态 |
| 输入解析 | 把用户说话或消息转换成可判断的交互状态 | 语音、文本或其他输入事件 | 输入类型、关联目标、上下文状态 |
| JEV 决策 | 基于同一份现场状态判断是否互动、互动对象、互动类型和强度 | 视觉状态、输入状态、时间状态、设备状态 | 结构化决策、概率、置信度 |
| 行为库 | 保存预设的动作、视觉反馈、声音和交互流程 | 行为 ID、参数、用户或场景配置 | 可执行的行为序列 |
| 调度与状态机 | 管理定时刷新、冷却、打断、优先级和交互状态 | JEV 决策、当前行为、用户事件 | 下一步行为、取消或延后指令 |
| 控制桥 | 把行为指令转换成机械臂和头部的运动控制 | 目标角度、速度、停留、动作参数 | 电机控制指令和执行状态 |
| 硬件执行 | 执行机械运动并产生用户可感知的反馈 | 控制指令、灯光/显示/声音指令 | 运动完成、异常、当前姿态和反馈状态 |

各模块通过明确的数据接口解耦。当前阶段选择对应的 JEV 提示词，JEV 输出基础动作选择；调度器将同一个回应事件分别发给机械臂控制桥和软件角色动画选择器。机械臂执行基础动作；软件端从当前阶段与该基础动作匹配、提前编排且骨骼支持的动画库中随机选择一个变体。持续视觉跟随仍独立运行，语言由独立 LLM 或预设素材负责。双端各自返回完成或异常状态，详见 5.2.4。

## 3.1 随头摄像头与视觉跟随（架构建议）

**连续跟随闭环：**图像帧 → 人物检测与跟踪 → 当前目标在画面中的水平偏差 → 跟随控制器 → 运动仲裁与控制桥 → 头部转动 → 新图像。目标是让当前人物留在画面中心附近；人物小幅晃动时设置死区与平滑，避免头部不停抖动。基础左右跟随可以从画面偏差控制开始，具体增益、视场、转动轴和相机标定需在实际机械臂上验证。

**行为决策闭环：**用户输入、人物进入或离开、定时刷新 → 当前场景快照 → JEV 选择预设行为 → 调度与行为库 → 同一运动仲裁器与控制桥 → 完成或异常回执。连续跟随不等待 JEV 每次返回；决策只改变“跟谁、做什么、什么时候做”。

**共享头部的处理：**跟随和摇头、探头等表演动作不能同时直接写电机。每个行为声明所占转轴、可打断点、最大时长和结束后的跟随恢复方式。表演期间继续采集图像；需要临时偏离目标时暂停对应轴的跟随，动作结束后先确认目标仍可见，再平滑恢复。只在经过验证的不同转轴上允许并行动作。

**目标与失踪：**用临时 track_id 维持同一个目标，人物左右移动不等于重新挑人；track_id 不代表真实身份。短暂遮挡先停住追随，超过配置时间再小范围找人，找不到回待机。不把画面大小直接当精确距离，不因另一个人一闪而过立即抢走目标。目标丢失、达到机械限位或帧过期时，由确定性控制逻辑降速或停止相应运动。

**接口约定：**感知输出 track_id、目标框或中心、可见性、观测质量、时间戳与帧对应的头部姿态；决策输出 target_id、behavior_id、强度档位和 state_version；行为库提供动作参数及跟随恢复规则；控制桥返回 command_id、执行中/完成/中断/失败和当前姿态。过期决策、未知行为 ID 和重复指令由调度层处理，完成状态以硬件回执为准。停止指令、限位和故障处理不经过模型判定。

技术参考：[ViSP 官方随臂摄像头视觉伺服示例](https://github.com/lagadic/visp/blob/master/example/servo-universal-robots/servoUniversalRobotsIBVS.cpp)。示例说明该类控制方法有实现基础，不代表本项目已完成适配或达到性能目标。

## 3.2 IP 配置与通用系统的接口（架构建议）

**系统机制与内容分离：**感知与硬件控制提供可复用能力；IP 配置声明形态、候选行为、互动条件、成长规则和呈现素材。JEV 读取当前 IP 配置、现场状态与成长记录，输出被允许的行为或形态；同一决策接口可服务不同 IP。

**建议的数据关系：**ip_id 对应 IP；form_id 对应该 IP 树中的节点；model_asset_id 引用节点的角色视觉／3D 模型，与 JEV 决策模型分别管理。节点关联图片、行为配置与允许的后继分支。运行状态保存当前模型引用、形态节点和进化路径；hardware_profile 描述实际硬件能力。

**更换 IP 的边界：**对于现有硬件已支持的能力，更换角色配置和行为内容应能复用感知、调度和控制链路。新增 IP 若需要新的动作、传感器或输出方式，仍需新增并验证相应模块；IP 配置不能凭空增加硬件能力。首轮先以牛来验证模块分离和完整运行链路。

## 3.3 云端网站、本机控制内核与真实硬件（2026-09-23）

**本轮已确认的产品方向：**网站部署在云端，展示一个真实硬件实例及其对应的软件状态；用户进入硬件连接模式后，通过当前电脑驱动机械臂等设备。页面需要说明宠物当前处于哪个等级、已经解锁什么、还可以从哪些方面进化。成长使同一硬件能执行更多已准备好的动作、声音与互动内容。牛来是首个展示 IP，控制内核应保持可复用。

**推荐连接方式：**云端网站 ↔ 云端会话与配对服务 ↔ 电脑上的本机连接程序 ↔ 机械臂、随头摄像头与电脑音箱。本机程序主动建立带身份认证的 WSS 长连接，浏览器通过云端订阅状态并提交高层行为请求。首版不要求用户开放电脑公网端口。该链路是待实现的工程建议，不表示目前已经连通。

云端保存会话记录、IP 配置、成长事件和网站可读取的状态投影；本机运行现场会话状态机、感知、行为调度与硬件适配，负责本轮状态转换和实际执行。网站发出请求，本机检查当前会话、等级、设备能力与控制权限后执行，回执再更新云端与页面。云端与本机不能各自独立升级；首版以本机产生的带序号事件驱动云端投影。网络中断时页面标记状态过期并停止接收远程控制，不重放旧动作；本机按已验证的设备停止策略处理。

**模型与控制边界：**JEV 继续负责在允许的行为集合内选择；Laya 仍是备选本机决策引擎。持续视觉跟随、电机轨迹、动作仲裁、限位与停止留在本机确定性控制逻辑中，不逐帧绕行云端，不等待模型批准。模型输出不能扩大能力白名单。

### 3.3.1 用户怎样连接

1. 当前保留 WORK 展示与进化树。后续设置独立硬件连接入口用于配对和设备状态；未配对时仅可浏览预览，不能触发机械运动。
2. 在要连接的电脑上启动本机连接程序，由程序生成短时、一次性配对码；网站输入配对码，本机确认匹配的网站会话。配对需绑定登录身份、电脑实例与有效期，并限制尝试次数。配对码不是永久访问凭据。
3. 在本机程序中选择机械臂和摄像头，完成所需系统权限与设备初始化。具体 USB、串口、蓝牙或厂商 SDK 路径以设备型号确定；声音首版可使用电脑或外接音箱。
4. 程序回传设备身份、支持的行为、就绪状态和时间戳后，网站显示对应设备。电脑在线不等于机械臂就绪；首次检查先读状态，实际运动另由现场用户触发。
5. 现场用户明确开始本轮控制，程序授予有有效期的单一控制租约。其他页面可观看但不能抢占。断开、租约失效或用户停止时撤销后续指令；重新连接需要重新确认控制，不自动恢复旧动作。

网页入口不提供虚假的“连接成功”、示例配对码或无效下载按钮。本机程序尚未交付时，显示“连接服务尚未接入”及连接步骤。安装本机程序是单独的交付动作，需经 Eric 明确批准。

### 3.3.2 进化与当前状态怎样对应

网站分别显示角色模型与进化状态、设备执行状态。当前可执行能力由当前形态的行为配置、硬件支持、已部署并验证的行为库及就绪条件共同决定。设备掉线不改变当前形态；进入新分支也不凭空增加硬件自由度、负载或运动范围。

| 维度 | 形态与资源的对应 | 页面应说明什么 |
|-|-|-|
| 角色模型 | 每个形态绑定对应的视觉／3D 模型。 | 当前模型与形态、资源就绪状态；模型未加载成功不显示进化已完成。 |
| 动作表达 | 当前节点配置对应动作与组合，不按统一阶段递增。 | 当前可用动作、候选分支差异及硬件是否支持。 |
| 声音与语言 | 各形态绑定相符的台词、音频与节奏。 | 素材是否就绪、由哪个设备播放；切换形态时同步配置。 |
| 进化路径 | 沿当前节点已定义的后继连接评估。 | 当前节点、实际路径、各分支条件；未定义的连接不自行补画。 |
| 硬件扩展 | 新增执行器、传感器或工具需实际适配。 | 独立说明支持状态，不随进化自动宣称获得。 |

网站使用 5.2 的六节点分支树，分别显示形态预览、实际运行形态和已走过的路径。新一轮现场培养从小牛开始，结束后复位供下一位使用；长期成长档案后续另行实现。当前代码只开放小牛和普通牛来的预览，六个节点都尚未绑定独立模型，使用标注的参考模型；外部已有图与模型不等于这些资源已经接入。没有真实会话时不能显示虚构等级或成长进度。

### 3.3.3 网站状态与执行证据

状态面板同时展示所连接电脑、真实硬件型号与设备标识、机械臂/摄像头/声音通道状态、本轮等级、当前行为与最近回执时间。连接进程至少区分未配对、等待本机确认、电脑在线但设备未就绪、可开始、执行中、已停止、失联及故障，并给出对应的下一步操作。渲染模型是角色展示；实物照片或实时画面尚未接入时不得称为实时硬件画面。

成长与行为共用 session_id、pet_instance_id、ip_id、form_id、hardware_id、bridge_id 和 state_version。行为请求另带唯一 command_id、behavior_id、有效期与控制租约标识；回执区分已接受、执行中、完成、中断、失败与结果未知。“已接受”不等于“已完成”。动作是否完成以设备可提供的回读证据为准；若只确认写入串口，则只能显示已发送。复合回应须收齐本次必需的动作与音频结果才能增加一次有效互动。

事件按会话与事件 ID 去重，状态按递增版本更新，重复回执不重复加经验，晚到结果不能进入新会话。断线时显示最后一次已知状态与时间；超时不能直接宣称失败或完成。重连先获取完整快照、核对未决指令和设备姿态，再允许新操作。网页“停止”需等待本机回执才能显示“已停止”；离线无法确认时提示使用现场停止入口，网页按钮不能替代设备物理急停。

### 3.3.4 实现顺序与验收

保留现有 WORK 大模型、进化路线、全屏树图和右侧观察区，先按 5.2 实现小牛的语言与动作约束，再接真实输入、JEV/LLM 状态、合法行为与执行回执，最后接入里程碑与分支转换。硬件配对、资源持久化、设备驱动仍为独立工程工作；不把 WORK 整页替换成实验成长控制台。演示动作计数、计时器和预览操作不能作为正式进化条件。

验收需覆盖未安装程序、配对码无效或过期、电脑在线但硬件缺失、正常动作完成、重复请求、拔线、停止、断线重连和上一轮晚到结果。视觉检查覆盖桌面与手机；等级增长必须由实际有效互动产生，不能由点击预览或升级动画产生。

**备选方案：**单台兼容串口设备可以评估浏览器 Web Serial，以减少安装步骤；但它需要安全上下文和用户授权，浏览器覆盖有限，而且不能自然统一摄像头、音频与多种厂商驱动。已有本机服务的项目也可以评估浏览器直连本机；其来源校验、配对、浏览器访问限制与兼容性需要单独验证。本项目首选本机程序主动连云端。参考：[MDN Web Serial API](https://developer.mozilla.org/en-US/docs/Web/API/Web_Serial_API)。

### 3.3.5 本地能力包与现有页面的衔接

**保留的本地优先方向：**模型文件、动作文件与声音素材优先保留在现场电脑，便于展示与状态同步，减少重复传输。后续明确保留原 WORK 页面，撤回整页替换为成长控制台的方案。核心交互沿用 5.2 的六节点进化树，本地能力包作为资源与执行基础，不改变页面主体验。

**本地保存和执行：**角色 GLB、纹理、动作配置、音频与进化配置组成可版本化的 IP 能力包。每个形态关联自己的模型和动作；分支文件声明合法后继与条件。本机保存当前节点、实际路径、执行结果与待同步事件，实时运动与停止由本机处理。目标模型、动作或必要资源缺失时，不执行进化切换；不能只改形态名称而保留旧模型。

**两类模型分开：**角色视觉／3D 模型确定优先放本地。AI 推理模型是否本地运行需按运行后端与设备性能验证；Laya 仍是候选，不将云端 JEV 宣称为已可本地部署。仅把 GLB 放本地不会消除云端决策延迟。若现场要求完整离线，界面、感知、语音、推理及其所有资源都必须在本机就绪。

**云端保留轻量同步：**同步身份与配对、能力包版本摘要、当前形态投影、进化事件、执行摘要及最后更新时间；默认不持续上传原始视频、音频、模型文件或高频关节数据。素材备份和分发可按需设计，不能与状态同步混为一谈。本机是单个现场会话的状态写入者；事件携带 session_id、event_id 与递增序号，恢复网络后补传并去重。云端不独立重复计算升级，旧指令不随重连重放。

**现场展示的推荐落点：**后续由本机程序提供本地界面和能力包读取，现场控制可在电脑内部完成；云端网站用于配对、同步与远程查看。仅有云端网页加本地文件导入，不等于完整离线可用。同机网页直连本机服务的权限、来源校验和配对另行验证；首版云端控制入口仍可通过本机主动 WSS 连接实现。

**界面实现范围：**WORK 保持角色展示与进化路线；右侧提供 Vision / Action、Large Language Model 切换和独立 JEV 决策卡片。连接后展示真实来源与状态，未接入时显示等待；示例模式明确标注且不控制硬件。资源导入、配对和设备维护作为后续专门功能，不占据整页替换现有体验。

仓库中保留了未挂载的 Hardware 实验控制台，包含浏览器内 GLB、动作、进化配置和音频导入逻辑；它不是当前 WORK 正式页面，也不是已安装的本机资源库。实验里的 normal/young/mature/hard 旧模板与演示回应计数必须在正式接入前对齐 5.2，不能作为新的产品依据。当前运行页面的进化树以 src/evolution.mjs 为准，预览不解锁形态。

正式本机能力包应补充资源哈希、版本、校验、原子切换与回滚；程序重启后恢复事件队列并校验现场设备状态。预计可减少素材传输和云端执行负担，但具体推理速度、设备响应与并发容量须实测，不预先承诺零延迟或完全离线。

# 4. JEV 在产品中的核心作用

JEV 是结构化决策层：接收场景状态与类型化问题，输出 Choice、Score 或 Noul 结果。牛来的主要动作路径使用当前形态提示词，从本次可用的少量基础动作中选择；软件衍生动画由独立选择器在提前规划的映射库内随机选择，不交给 JEV 临时生成。Choice 与 Score 提供概率分布和 confidence；Noul 返回命题为真的概率，没有独立 confidence 字段。JEV 不承担骨骼轨迹生成、视觉测量、电机轨迹或硬件保护。接口依据：[Cloudflare JEV 官方接口说明](https://developers.cloudflare.com/ai/models/typesafe/jev/)。

| 原语 | 回答的问题 | 桌面宠物中的候选用途 |
|-|-|-|
| Choice | 从预先定义的选项中选哪一个？ | 选择互动对象、互动模式、行为 ID、设备路径或下一步处理器。 |
| Score | 当前状态处于有序尺度的哪个位置？ | 根据明确量表选择互动积极程度、行为强度档位或优先级。距离与跟踪质量由感知模块测量，电机幅度和速度由控制层限制。 |
| Noul | 某个明确命题为真的概率是多少？ | 判断当前是否适合主动邀约、是否应回应或是否适合切换互动。急停、限位、失联等硬件保护由确定性规则直接执行。 |

三种原语可基于同一份场景快照评估不同问题；独立问题可合并请求。若问题依赖上一问的结果，应分步处理或由程序约束候选项。各类型分别设置阈值与回退，低置信度或超时不触发新的复杂动作；模型不可用时仍保留有效视觉输入下的基础跟随、明确停止和故障保护。

## 4.1 备选方案：Laya 本机决策与实时互动控制

**方案定位。**Laya 作为本黑客松桌面宠物项目的备选决策引擎，后续可探索部署在电脑本机，通过控制桥驱动硬件互动。目前处于方案储备阶段，尚未安装、接入或完成本机性能验证；是否替换 JEV，待实验结果决定。

**模型介绍。**Laya 是开源的非自回归结构化决策模型，采用 Apache-2.0 许可证。它接收文本或 JSON 状态及预先定义的问题，输出 Choice（选项）、Score（有序评分）、Noul（命题概率）等结果，不生成聊天回复或动作代码。官方提供约 421M 参数的英语和 typed-decisions 版本，以及约 322M 参数的多语言版本。中文互动可优先评估多语言版本，实际效果需验证。

**本机部署的价值。**在电脑本地完成语义判断，可减少决策环节对云端网络的依赖，探索更稳定的互动响应时间，并减少向外发送现场状态。当前已确认的实验电脑为 Apple M4、16GB 统一内存，可作为单模型推理验证平台；实际内存、运行后端兼容性和延迟仍需实测。若要求完整离线，视觉感知、语音识别等上游模块也需要本地运行。

**候选运行链路。**摄像头识别与输入解析 → 现场状态 JSON → 本机 Laya 选择互动对象或预设行为 → 调度状态机与行为库 → 控制桥 → 机械臂、头部、灯光或声音反馈。示例：用户说“看我这边”，视觉模块提供人物位置，Laya 根据话语与当前互动状态选择注视行为，再由行为库和控制桥执行。这里的实时控制指及时选择互动行为，电机轨迹、限位、速度约束与急停仍由确定性控制逻辑负责。

**模块化接入。**快速决策层保留统一适配接口：输入为现场状态、候选行为与问题定义；输出为决策值、概率、模型版本、状态时间戳和错误状态。JEV 与 Laya 分别作为云端和本机实现，切换实现时复用视觉模块、行为库和控制桥。两者置信度不能直接共用同一阈值，需分别用项目数据校准。

**能力边界与回退。**本方案采用的 Laya 文本模型不直接读取原始图片或音频，需由感知模块先转换为可用状态。基础模型的零样本效果不能等同于领域微调版本；应先评估，再按需要微调和校准。低置信度、超时或状态过期时，由状态机进入预设待机、保持或安全停止行为；是否调用 JEV 进一步判断属于后续可选策略，不能默认形成云端依赖。

**后续验证。**使用桌面宠物的真实中文指令和现场状态，比较本机 Laya 与 JEV 的行为选择准确率、误触发率，以及从事件发生到硬件开始响应的 p50/p95 延迟。同时检查模型冷启动、持续运行内存、功耗，以及与视觉模块并行运行时的表现。官方 GPU 测速不能直接视为这台 M4 或完整硬件链路的响应时间。

资料来源：[Laya 官方仓库、模型说明与性能限制](https://github.com/NandhaKishorM/laya)；记录日期：2026-09-22。

# 5. 核心交互流程

**主动交互。**系统按照时间间隔或现场事件刷新状态，视觉模块提供人物和设备状态，调度器把状态交给 JEV。JEV 判断是否值得互动、选择对象和行为类型，并给出互动强度或优先级。调度器检查冷却、当前行为和安全条件后，从行为库取出预设行为，再交给控制桥执行。

**被动交互。**有效话语、文本、触碰或感知事件进入当前会话。JEV 使用当前阶段提示词，在可执行的基础动作中选择一个；调度器以同一回应事件触发机械臂基础动作和软件角色的对应随机衍生动画。软件变体必须提前规划，匹配阶段、基础动作语义与骨骼。LLM 独立提供阶段适配的语言，小牛可以仅动作或短音节。各端完成状态分别更新，只有符合 5.2 里程碑的可信记录才影响进化。

**统一执行原则。**视觉跟随与行为决策各自运行，通过同一运动仲裁器控制机械臂。每轮行为执行状态回写后，再判断继续、结束还是恢复跟随。分别记录视觉到朝向、模型判断、决策到动作的延迟，以及误跟踪、误触发、打断和恢复表现；不把模型延迟等同于整机响应时间。

## 5.1 角色模型与树状分支进化

**2026-09-23 已确认：**IP 形态按树状关系发展，每个形态关联对应的角色视觉／3D 模型，当前形态及其表现跟随角色模型状态。通用系统承载模型与节点的关联、进化分支、条件判断及状态转换；各 IP 定义自己的树。撤下此前的线性能力分级，不预设统一阶段数量、固定顺序或最终形态。

| 系统元素 | 定义 | 接口建议 |
|-|-|-|
| 形态节点 | 树中的一种角色形态，每个形态绑定对应的视觉／3D 模型。 | 形态标识、模型资源、图片、互动配置及允许的后继节点。 |
| 角色模型状态 | 当前使用的角色模型及与该形态对应的呈现状态。 | 记录资源标识、版本、加载状态和当前形态；具体动画等字段随素材类型确定。 |
| 进化分支 | 从一个节点到另一个节点的允许转换。 | 分别定义起点、目标、条件和进化表现；树的实际连接由团队填写。 |
| 当前运行状态 | 当前模型、对应形态及实际经过的进化路径。 | 保存当前节点、模型引用、分支历史和互动上下文，不只保存一个数字等级。 |
| JEV 决策 | 根据互动与当前状态评估允许的行为或进化分支。 | JEV 是决策模型；角色视觉／3D 模型是呈现资源，两者分别管理。 |

**分支规则：**进化沿树中已定义的连接进行。兄弟形态不默认存在高低关系，也不默认继承彼此能力。能否回退、重选分支或切换已解锁形态，按 IP 规则定义；调用失败或设备异常不自动退化。

**建议的进化闭环：**读取当前角色模型状态和对应节点 → 获取合法后继分支 → JEV 结合互动证据评估分支条件 → 校验目标角色模型、素材与硬件能力 → 在当前回应结束或可打断点切换 → 新模型、形态与互动配置一致生效 → 保存路径并更新前端。条件未满足时继续当前形态；资源未就绪时不宣告进化成功。

**呈现与状态一致：**每个形态分别关联角色视觉／3D 模型、展示素材与互动内容。进化后不能只改名称而继续展示旧模型。JEV 负责判断，资源管理与状态机负责模型加载和一致切换；不因每形态有一个角色模型就推定需要单独训练一个 JEV。

## 5.2 展示 IP：牛来的形态与交互内容

**本轮核心体验定义（2026-09-23）：**牛来从表达模糊、语言很少的小牛开始，在与同一位参与者的互动中逐渐形成回应能力和性格。沿当前代码已经定义的两条路径成长：小牛 → 普通牛来 → 骚牛 → 仙牛；小牛 → 普通牛来 → 硬牛 → 暗黑牛。本节确定首版的互动和进化规则；新增规则是待实现的产品目标，当前网页并未运行完整成长闭环。

### 5.2.1 进化树与共同体验

六个节点与 src/evolution.mjs 一致：calf（小牛）、normal（普通牛来）、playful（骚牛）、tough（硬牛）、celestial（仙牛）、dark（暗黑牛）。小牛是新一轮培养的起点，普通牛来是共同成长节点，之后形成两种性格方向。骚牛和硬牛、仙牛和暗黑牛分别是同层分支，不互为升级关系，也不因某条路线更难而奖励更强的硬件能力。

**进化带来的变化：**用户先感到“它注意到了我”，再感到“它接得住我的回应”，最后感到“它有自己的性格，也懂得我们的相处方式”。阶段改变 JEV 的提示词、软件角色、可选的预编排衍生动画及语言表达预算。机械臂继续使用同一组已验证的基础动作，软件通过骨骼动画呈现更丰富的性格。更成熟不等于说得更多；仙牛和暗黑牛都可以安静陪伴。

同一轮只走一条分支，不跨节点跳级，不在骚牛与硬牛之间随意切换。到达仙牛或暗黑牛后继续日常互动，不再虚构下一等级。用户可以明确结束并重新培养，从小牛开始体验另一条路线；预览树节点不改变运行形态。暂时没有回应、设备断开或模型调用失败不导致退化。

### 5.2.2 六种形态的交互与表达

| 形态与气质 | 用户怎样互动 | 牛来怎样回应 | 语言与新增体验 |
|-|-|-|-|
| 小牛 calf：懵懂、试探 | 打招呼、轻点角色、移动到它的视线中、把一个东西指给它看，再回应它的小反应。 | 看向你、小幅歪头、轻轻低头再抬起；先动作，再等待。听不清或不理解时保持关注，用疑惑姿态回应。 | 大多数回应不说话；需要发声时每次最多一个短音节或叠音，如“哞？”“嗯～”“咦”。不说完整解释、长句、哲理或成熟笑话。 |
| 普通牛来 normal：开始接得上话 | 让它看一个明确目标，邀请做一个已支持的小动作，给出肯定或简单纠正。 | 注视与点头有明确对象；能在当前会话里接住上一轮指代，被纠正后改变回应。 | 每次最多一句短句，默认不超过 12 个汉字，如“好的呀”“我试试”“知道啦”。开始表达简单意愿。 |
| 骚牛 playful：爱玩、爱表现 | 邀请它逗你开心、模仿一个已支持的姿态，或用友好的玩笑接住它的表演。 | 歪头、抬头、停顿与小幅动作组成短表演；得到回应后可以再玩一次，用户没有接话则收住。 | 每次最多一句短句，默认不超过 20 个汉字；语气俏皮，如“看好啦”“我就说我有点牛”。“骚”指活泼爱表现，不指冒犯或性暗示。 |
| 硬牛 tough：认真、有主见 | 提出一个具体可做的小请求，让它尝试，并告诉它做得怎样；也可以温和纠正或改变请求。 | 先看目标，再做明确的点头或转向；遇到做不到的事情会停住或拒绝，不用更大幅度硬撑。 | 每次最多一句短句，默认不超过 16 个汉字，如“我试试”“这个我暂时不会”。体验重点是认真回应和有边界。 |
| 仙牛 celestial：轻松、从容 | 既可以一起玩，也可以说“陪我待一会儿”或明确表示需要安静。 | 减少抢话和连续表演，用缓慢的小幅转向、短暂停顿或安静注视保持陪伴；被邀请时才展开表达。 | 默认不超过两句短句、合计 32 个汉字；按需要使用已有随想素材。轻巧、有余味，不每次都讲道理。 |
| 暗黑牛 dark：沉稳、克制 | 让它陪着完成一个明确的小事，给出“先等等”“继续吧”等清晰的节奏反馈。 | 通过注视、低头、短促确认和留白表现存在感；等待后只有收到新的有效邀请才再次行动。 | 默认不超过两句短句、合计 24 个汉字，如“我在”“准备好了再叫我”。气质冷静，不以恐吓、羞辱或无条件服从表现“暗黑”。 |

**小牛的“模糊”落实在表达上：**它的反应带有探索感，意图主要靠目光、姿态和短音节传达，用户不需要立即读懂每一个动作。保持角色主体可见，不能用模糊状态掩盖录音、断线或错误；“正在听”“未连接”“请重试”等系统提示始终清楚。基础理解、停止、退出和被纠正的能力从小牛就存在。当前树中未揭示节点的模糊遮罩只表示尚未发现，不等同小牛的表达设定。

以上字数是首版中文角色输出预算，英文使用对应的短音节、短句与句数限制；它们约束角色台词，不限制用户自然表达，也不限制系统错误说明或观察区的决策摘要。超出阶段预算的生成内容先重写或退回该形态素材，不直接截断播音。不以词多词少判断用户是否完成互动。

### 5.2.3 怎样进化：五条边与互动证据

**用经历形成里程碑，不用统一经验条。**一个有效互动事件至少包含：本轮参与者的有效输入、牛来的实际回应、对应的完成状态和事件标识。需要用户反馈的里程碑，在用户明确回应后才成立。下表的条件为“同时满足”；同一事件只能记一次，同一种经历重复刷不增加新里程碑。JEV 可判断语义类别，状态机依据证据和合法连接决定是否提交进化。

| 允许的进化 | 必须形成的经历 | 用户能感到的变化 | 不能作为替代条件 |
|-|-|-|-|
| 小牛 → 普通牛来 | 建立回应：用户打招呼，小牛完成一次关注回应；共同注意：另一事件中，用户引导它关注一个可确认目标，小牛成功回应；反馈确认：用户对其中一次回应给出明确肯定，或纠正后确认新的回应。三项齐备。 | 第一次用清楚的短句接住用户，例如“好的呀”，随后在新形态继续关注当前参与者。 | 页面打开时长、连续点击、播放任意三段音频，或仅凭它自己说“我懂了”。 |
| 普通牛来 → 骚牛 | 进入普通牛来后，用户邀请玩耍，牛来完成一个允许的俏皮回应；用户明确接住并继续邀请；牛来完成与前一次有变化的第二个玩耍回应。形成双向玩耍的经历。 | 从简单确认变为短表演与俏皮回应。揭示骚牛节点，记录“我们开始一起玩了”。 | 只检测到一个“好玩”关键词、旁人的笑声，或把任何表扬都算作玩耍。 |
| 普通牛来 → 硬牛 | 进入普通牛来后，用户提出可执行的小请求，牛来完成；随后用户调整目标、顺序或提出温和纠正，牛来按新的有效输入完成第二次回应并获得明确反馈。形成合作与修正的经历。 | 回应更明确，表达“愿意尝试，也知道什么时候停”。揭示硬牛节点。 | 用户语气强硬、辱骂、重复命令、要求更快更猛，或执行未完成的请求。 |
| 骚牛 → 仙牛 | 在骚牛形态中已有一次成功的双向玩耍；随后用户明确转向安静或陪伴，牛来停止主动表演并完成允许的陪伴回应；用户之后主动反馈认可。形成“会玩，也懂得收住”的经历。 | 进入更从容的表达，保留玩心并尊重节奏。用一个简短出场回应，不连续播放长台词。 | 用户沉默本身、退出要求、靠不停说话刷次数，或把“停止”当作鼓励继续互动。 |
| 硬牛 → 暗黑牛 | 在硬牛形态中完成一次合作回应；之后一次互动中，用户要求等待，牛来按当前允许的保持/回正行为完成等待状态转换；用户主动发出新的邀请，牛来重新校验状态并完成回应，最后得到明确反馈。形成可靠且有边界的合作。 | 进入克制的确认与陪伴；不抢先执行、不自动重放等待前的动作。 | 故障恢复、被迫服从、用户负面情绪，或执行器仍未确认完成。 |

**分支冲突处理：**普通牛来只评估当前两条合法后继，证据从进入普通牛来后开始收集。仅一条满足时进入该分支；两条同时满足时保持普通牛来，用“逗你玩，还是帮你做？”这样的短问句澄清本轮偏好，用户明确选择后再提交。不能用用户性别、外观、语气强弱或随机数决定分支。未达到条件、语义不确定或用户不想选择时，继续当前形态。

**证据与真实输出对应：**一个只需动作的回应在动作回执完成后即可成为证据；一个只需声音的回应以声音实际播放完成为准；复合回应必须收齐其必需输出。LLM 文本输出完毕、请求已发送和网页计时器结束，都不能代替机械动作回执。没有视觉识别能力时，不宣称已看懂用户展示的物体；可以通过明确文字引导进行相应互动。

初版不设置“聊满多少轮必定升级”或自动补齐证据。达到条件后等待当前回应结束，再检查目标形态的模型、必要动作和声音资源。资源就绪才切换；资源缺失显示“进化条件已满足，形态资源未就绪”，保持当前形态且保留本轮证据。每次转换携带唯一事件标识，重复或旧会话事件不重复进化。

### 5.2.4 阶段提示词、基础动作与软件衍生动画

**已明确的动作链路：**当前阶段选择对应提示词 → JEV 根据输入和现场状态选择一个基础动作 → 同一回应事件分别驱动机械臂与已绑定的 WORK 页面。机械臂执行该基础动作；软件角色从该基础动作对应、当前阶段允许、已经提前规划好的衍生动画中随机选一个播放。角色模型已做骨骼绑定是软件丰富表现的前提；每个可播放动作仍要有明确的动画资产或预编排配置。

**三种职责分开：**JEV 选择基础动作的语义，不直接生成关节轨迹，也不临时发明软件动作；机械臂适配器执行预设基础动作；软件动画选择器在许可候选集中随机选变体。语言由独立 LLM 或预设素材负责。进化改变阶段提示词和软件表现，不要求为每个阶段训练一个新的 JEV，也不把软件动作数量当作机械臂能力数量。

**共同提示词约束：**“你负责为牛来选择下一次基础动作。读取当前阶段、当前有效输入、感知摘要、最近回应和可用基础动作，只从本次提供的候选项中选择一个。阶段描述影响选择偏好，不能突破候选动作和执行条件。不确定、没有合适动作或当前不应回应时选择 WAIT。不要生成机械轨迹、代码或软件动画名称。”这段作为各阶段共用约束；WAIT 是不启动新动作的控制结果，不新增一个机械动作。

| 阶段提示词 | 本阶段判断重点与动作偏好 |
|-|-|
| 小牛 calf | “你还在试探着认识对方。把注意到、疑惑和温和靠近的感觉放在表达之前。优先用看向对方、轻轻歪头或低头回应；不要把长问题处理成复杂表演，不连续争取注意。”角色只输出无声动作或少量短音节。 |
| 普通牛来 normal | “你开始能接住对方的邀请。先确认当前在说谁、指什么和要做什么。明确认可时点头，不确定时歪头，被纠正时收住并重新关注目标；不要只根据单个关键词选动作。” |
| 骚牛 playful | “你活泼、爱表现，但只在对方愿意玩时接住玩笑。根据语境选择适合俏皮表现的基础动作；用户继续邀请时允许变化，用户安静或拒绝时收住。不要为热闹而扩大机械动作。” |
| 硬牛 tough | “你认真、有主见。优先用明确注视、点头或收敛回应具体请求，接受温和纠正；设备不支持就等待或表达边界，不逞强，不把强硬语气当成扩大能力的授权。” |
| 仙牛 celestial | “你从容，能分辨对方想玩还是想安静。减少重复表演，优先选择注视、短暂停顿后回应等克制动作；被邀请时可以轻巧表达，不主动打断对方。” |
| 暗黑牛 dark | “你沉稳、可靠，尊重约定的节奏。用注视、低头、简短确认或等待表达存在感。等待后只有新的明确邀请才启动动作，不自动重放，不用攻击性或更大幅度表现性格。” |

阶段提示词与 form_id 一一绑定，切换形态时切换 prompt_version；共用系统约束保持一致。各阶段复用基础动作集合，表中的“优先”是选择偏好，不代表幼年失去点头、停止或接受纠正的能力。行为是否可用仍取决于当前硬件和状态。成长里程碑可由独立的结构化评估产生，不把选择动作本身当作升级。

**动作标识与执行映射：**最终 base_action_id 对应下表中的具体动作，保持身体转动与头部转动、左右方向和目标姿态可区分。旧实验配置的 look、bow、nod、tilt、reflect 可保留作语义或动画标签；除已明确对应的点头、歪头外，不直接据这些名称推断关节动作。“低头”“停顿后回应”等表现需要关联到已规划的基础动作或组合后才能进入可执行候选。关节编号不包含角度、正负方向、速度、回正位置或组合时序，这些参数另由动作配置定义。2、3 号联动与 3 号点头共用关节，执行时由同一调度器仲裁。软件变体不改写该机械动作的目标与参数。

**机械臂基础动作与新代码关节对应（Eric 提供）：**以下动作与关节编号以本次提供的映射表为准，替代先前依据实验配置暂拟的硬件动作分类。左／右、坐下／站起／中间姿态是组内不同的明确动作选项；JEV 选择具体动作后，软件只随机其同义的预编排表现。第三列为软件动画规划示例，仍需逐项绑定与验证。

| 动作 | 新代码中的关节 | 软件端衍生动画规划示例 |
|-|-|-|
| 身体左右转 | 1 号 | 对应角色转身、侧身看向目标或带性格的身体朝向变化；只在与本次转向含义一致的预编排变体中选择。 |
| 坐下、站起、中间姿态 | 2、3 号联动 | 分别映射到当前阶段的坐下、站起或中间姿态动画，例如轻轻坐下、利落起身；坐下与站起不得互相随机替代。 |
| 点头 | 3 号 | 小牛试探点头、普通牛来点头回应、骚牛得意点头、硬牛抱臂点头、仙牛轻点头等提前规划的阶段变体。 |
| 左歪头、右歪头 | 4 号 | 懵懂歪头、好奇侧头、俏皮探头等阶段变体，保持本次选定的左右方向和表达含义。 |

**软件随机选择规则：**候选动画必须同时匹配当前角色与形态、JEV 选中的 base_action_id、上下文标签和当前骨骼；动画资源已加载、已审核且本轮可执行。优先排除刚播放的同一变体；只有一个可用变体就固定播放，没有匹配项则使用该基础动作预设的通用变体，否则保持 idle 并报告“动画未就绪”。不从其他基础动作或未解锁形态借动画，不运行时生成新动作。首版用等概率选择即可；最终 animation_variant_id 留在事件记录中供复现。

**同时响应与回执：**JEV 返回后，调度器创建同一个 response_id，锁定 session_id、form_id、prompt_version、base_action_id 与本次选出的 animation_variant_id，向机械臂适配器和绑定页面发出同一回应事件。两端可以并行开始，不要求逐帧相同，也不因 JEV 较快返回就声称硬件动作完成。事件重复不重复执行；切换视图不重新随机抽取动画。动作完成后各自回正或回 idle，再恢复原有跟随。

硬件联动模式下，机械臂与软件角色分别显示执行状态；一端成功另一端失败时如实展示部分完成，不记作需要双端完成的成长证据。硬件离线时可在明确的“仅软件演示”模式播放动画，不能冒充硬件联动成功；软件演示的培养记录与真实会话隔离。两端共用停止和会话失效规则，迟到事件不驱动新形态。现有 WORK 页面作为软件表现与观察端，其资源与实时事件订阅的接入情况分别核对。

**LLM 负责表达：**独立生成符合当前形态预算的文本。小牛可以不发起语言生成，直接使用短音节或无声回应；普通牛来及后续形态逐渐开放短句和性格化表达。LLM 慢或不可用时，JEV 仍可选择合法动作，语言退回当前形态素材。JEV 或设备不可用时，对话可继续，但不能借语言假称动作已完成。当前已有实现仅为预设演示，真实模型接口仍待接入。

动作与语言共享本轮会话、输入事件和形态版本，迟到的上一轮回复不能覆盖新形态。涉及“已经点头”等动作事实，语言必须等对应回执；尚未完成时使用准备中、暂时不可用等准确表述。小牛的长篇生成文本不能通过观察面板绕过表达预算，用户看到和听到的角色回复保持一致。

WORK 右侧沿用当前代码的 Vision / Action 与 Large Language Model 切换。前者展示相机来源及动作状态，后者展示有效输入、角色回复和流式状态；下方 JEV 卡片独立显示感知摘要、动作选择、简短决策说明与执行回执。决策说明是可读的状态摘要，不包装为模型完整的内部思考记录。相机、语言流和决策流各自标示连接状态；断线保留最后已知状态和时间，并清楚标记过期。

保留打招呼、新事物、设备离线三组观察面板示例，以及暂停、继续、重播、返回实时的交互。示例不执行硬件、不积累成长证据；长句示例也不代表小牛正式具备相同语言能力。JEV 固定问答入口用于讲解产品，不能当作角色会话或成长记录。

### 5.2.5 一轮体验与前端反馈

**开始：**用户明确开始一轮培养，载入小牛和该形态的表达配置。现场每轮关注一位参与者，通过互动位置与前端选中框确认，必要时由现场人员选择。旁人出现不抢占目标；短暂遮挡先等待，无法确认原对象时暂停，不接入他人的上下文。

**互动：**用户自然说话或输入文字，无须背口令。首版现场输入采用点击或按住收音，展示“可以说话／正在听／正在回应”；识别失败可重试或改用文字。点击角色是一次触碰事件，拖动只改变展示朝向，鼠标跟随只改变网页角色的注视；不能把这些网页动作称作真实摄像头识别。待真实输入接入后，触碰、话语与感知事件由同一会话管理。

**成长反馈：**完成一个新里程碑后，用一句简短提示说明实际发生的变化，例如“它开始回应你的邀请”。用户主动展开进化树时，可看到已走路径、已获得的经历和下一步自然互动提示；默认不显示生硬的刷分任务。当前形态明确显示，未揭示分支继续遮罩；解锁后再揭示对应节点和形态介绍。技术流式内容放在观察区，不强制普通参与者阅读。

**形态切换：**当前回应结束、资源就绪后提交新形态，模型、形态名、声音与行为配置同步生效。展示短暂变化和一句符合新形态的回应，不自动连续跨两个节点。加载失败时回到原形态并提供重试，不能只改名称或用参考模型冒充目标形态已完成。

**结束与恢复：**“先等等”暂停后续互动，只有新的明确邀请才继续；“停止／结束”直接结束本轮，不挽留、不触发进化。退出、刷新或换人不自动发起真实动作。现场展示默认按会话培养，结束后清理参与者、待执行内容和旧决策，并在设备复位确认后供下一位从小牛开始。跨会话长期成长档案作为后续能力，不假设当前 localStorage 已保存培养状态。

**主动互动：**新参与者确认后最多主动试探一次，等待用户回应；没有回应就安静，不靠循环喊叫争取注意。首版普通主动邀请至少间隔 30 秒，且只在目标可见、没有收音或播放、没有动作、未暂停时评估；小牛以无声试探为主。该时间是可调的体验初值，不是模型延迟承诺。用户再次发起有效输入可立即触发被动回应。安全停止、退出、失联与限位始终优先。

### 5.2.6 动作与声音素材的阶段约束

基础动作词汇及其软件衍生映射统一按 5.2.4 管理，回正、idle 和停止另作为必要恢复与控制状态。形态差异通过阶段提示词、衍生动画库、语言、节奏和使用时机表现，不随成长增加未验证的机械速度、幅度或负载。软件角色的挥手、舒展或抱臂等骨骼动画不等于机械臂能执行同样动作。表演占用转轴时，连续跟随让出该轴，表演结束后确认原目标再恢复跟随。

声音沿用 src/voices.json 的素材标识：okay（好的呀）、not-true（才不是呢）优先给普通牛来及后续形态；jump-later（我还是长大一点再跳吧）作为适配性格的回应素材，不代表已解锁跳跃；growing、tomorrow、same-different 等完整随想优先用于仙牛或其他明确配置的成熟表达，不在小牛阶段随机播放。文档示例台词未对应文件的部分仍需录制或经过语言与声音输出链路实现。

保留旧候选素材编号便于追溯：L1-01、L1-02、L1-03 是“妈妈”语气变体候选；L2-03、L2-04、L2-12、L2-11 分别对应得意、尝试、接受纠正、能力边界；L2-05 对应 jump-later 摘录。旧 L1/L2 是素材编号，不是新增进化节点，也不自动授予播放权限。摘录出处与使用记录保留原素材说明，尚未核对的归属不写成已核验。

**World 彩蛋独立保留：**当前代码由收集全部 27 个不同星光解锁 mama 音频，循环播放可停止。这个彩蛋不直接升级形态、不选择分支，也不因“小牛语言少”就自动解锁；现有 mama 文件继续遵守该锁。小牛的常规短音节需要单独准备，不借用彩蛋绕过解锁。网页收集进度与培养会话、硬件回执分开保存。

### 5.2.8 核心体验验收

1. 小牛面对问候、夸奖、长问题和重复点击，仍以无声动作或单个短音节回应；不会随机播放完整随想。听不清时系统提示清楚，要求停止时立即退出后续互动。
2. 只有建立回应、共同注意与反馈确认三类经历齐备，才可由小牛进化为普通牛来；一直挂机、重复输入、点击预览或重播示例均不进化。
3. 同样从普通牛来开始，双向玩耍可走向骚牛，合作与修正可走向硬牛；证据混合时澄清，证据不足时保持形态，不随机分支。
4. 骚牛能接住安静陪伴的邀请，硬牛能等待新的明确邀请；只有相应经历和反馈完成才分别到仙牛或暗黑牛。结束或故障不被当成进化契机。
5. LLM 的长句、超时、迟到回复不能越过阶段预算或控制动作；JEV 动作选择、设备执行和结果状态分别显示，设备离线时不报告动作成功。
6. 同一基础动作在软件端可以呈现不同的预编排变体，机械臂仍执行对应基础动作。候选始终匹配阶段、语义与骨骼；切换标签或重收同一事件不重新抽取或重播，空候选不借用其他动作。
7. 改变阶段后 JEV 使用对应 prompt_version；旧阶段的迟到决策与动画无效。双端回执分开记录，硬件联动模式下一端失败不记完整成长证据，仅软件演示不冒充实机结果。
8. 目标形态模型或必需素材缺失时维持原形态，保留本轮证据并可重试；重复回执不重复转换，换人后旧事件不进入新会话。
9. World 的 27 星光只解锁既有 mama 彩蛋；培养路径不因彩蛋播放改变。六节点预览与实际培养状态区分明确。
10. 连续五轮现场体验能正确开始、互动、结束和复位；允许停在任意已到达形态，不以强制通关作为成功标准。

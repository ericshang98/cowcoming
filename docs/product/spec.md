# 1. 产品定位

**项目主体是一整套可承载不同 IP 的软硬件交互系统。**系统提供感知、结构化决策、行为调度、成长与形态解锁、硬件控制等可复用能力。JEV 作为当前方案中的决策模块，连接现场状态与预设行为。**“牛来”是运行在这套系统上的一个 IP，也是项目展示的一部分。**系统名称尚未确定，文档标题使用描述性名称。

**产品价值：**让不同 IP 能够通过同一套系统感知环境、及时回应用户，并用各自的行为与成长形态呈现连续的互动体验。当前以机械臂桌面宠物原型验证这套链路；通用能力与具体 IP 内容分别设计和维护。

## 1.1 系统、IP 与展示的边界

| 层次 | 负责的内容 | 与牛来的关系 |
|-|-|-|
| 通用软硬件系统 | 感知接口、场景状态、JEV 决策接口、行为执行与调度、成长进度、硬件适配和执行反馈。 | 承载牛来及其他 IP 的共同能力。具体接口设计仍待实现与验证。 |
| IP 内容与配置 | 角色名称与设定、形态与成长路线、互动规则、动作与反馈素材、模型判断标准及候选行为。 | 牛来拥有自己的一套内容与配置；其他 IP 可定义不同表现和成长路线。 |
| 展示实例 | 选定的 IP、实际硬件、现场演示流程及这次开放的能力。 | 牛来结合当前机械臂和随头摄像头，展示系统的一部分能力；展示范围单独确定。 |

**三个独立维度：**IP 表示角色是谁；形态是该 IP 进化树中的节点，绑定角色视觉／3D 模型；硬件载体表示用什么设备呈现。普通牛来、幼年牛来、成熟牛来、硬牛等属于同一 IP，树中关系待定义。其他 IP 可复用系统并定义各自的模型与分支。

# 2. 当前已确认的产品方向

**当前展示原型的硬件形态。**本轮用机械臂作为载体，头部可以转动，外部套上头套，以头部和机械臂的预设动作表达反应。摄像头安装在末端，随头部视线一起转动。该硬件用于牛来 IP 的展示验证；灯光、屏幕、扬声器等附加反馈设备尚未确认。其他硬件的适配属于可扩展方向，不能视为已经支持。

**视觉能力。**已确认需要人物检测与视觉跟随：机器人关注一个目标人物，人物左右移动时，头部和摄像头跟着转动。初始关注附近的人；多人切换规则仍需讨论。用户同时提出“识别男女”的需求，具体用途与技术方案尚未定案。摄像头外观不能确认人的性别身份；建议将性别或称呼偏好设计为用户自选且可不填写的信息，用于称呼配置，不作为跟踪、亲疏或互动优先级依据。人物身份、手势、头部姿态等识别能力各自作为可替换模块评估。

**交互方式。**产品同时支持主动交互和被动交互。主动交互由系统按时间或现场状态刷新后触发判断；被动交互由用户说话或发送消息触发。

**第一版约束。**第一版不依赖大语言模型生成回答。机械臂动作、头部动作、视觉反馈、声音和互动流程以预先设计好的状态与行为模块为主；JEV 负责在现场状态下进行快速判断、选择和路由。

# 3. 模块化系统架构

| 模块 | 职责 | 主要输入 | 主要输出 |
|-|-|-|-|
| 视觉感知 | 检测周围的人并维护人物跟踪状态 | 摄像头画面、设备位置、历史跟踪状态 | 目标数量、目标位置、距离、跟踪稳定性等状态 |
| 输入解析 | 把用户说话或消息转换成可判断的交互状态 | 语音、文本或其他输入事件 | 输入类型、关联目标、上下文状态 |
| JEV 决策 | 基于同一份现场状态判断是否互动、互动对象、互动类型和强度 | 视觉状态、输入状态、时间状态、设备状态 | 结构化决策、概率、置信度 |
| 行为库 | 保存预设的动作、视觉反馈、声音和交互流程 | 行为 ID、参数、用户或场景配置 | 可执行的行为序列 |
| 调度与状态机 | 管理定时刷新、冷却、打断、优先级和交互状态 | JEV 决策、当前行为、用户事件 | 下一步行为、取消或延后指令 |
| 控制桥 | 把行为指令转换成机械臂和头部的运动控制 | 目标角度、速度、停留、动作参数 | 电机控制指令和执行状态 |
| 硬件执行 | 执行机械运动并产生用户可感知的反馈 | 控制指令、灯光/显示/声音指令 | 运动完成、异常、当前姿态和反馈状态 |

各模块通过明确的数据接口解耦。视觉跟随负责持续朝向当前目标，JEV 负责选择互动对象与行为，行为库负责预设动作，控制桥负责执行。识别算法、决策引擎、行为内容和控制协议可以独立替换。

## 3.1 随头摄像头与视觉跟随（架构建议）

**连续跟随闭环：**图像帧 → 人物检测与跟踪 → 当前目标在画面中的水平偏差 → 跟随控制器 → 运动仲裁与控制桥 → 头部转动 → 新图像。目标是让当前人物留在画面中心附近；人物小幅晃动时设置死区与平滑，避免头部不停抖动。基础左右跟随可以从画面偏差控制开始，具体增益、视场、转动轴和相机标定需在实际机械臂上验证。

**行为决策闭环：**用户输入、人物进入或离开、定时刷新 → 当前场景快照 → JEV 选择预设行为 → 调度与行为库 → 同一运动仲裁器与控制桥 → 完成或异常回执。连续跟随不等待 JEV 每次返回；决策只改变“跟谁、做什么、什么时候做”。

**共享头部的处理：**跟随和摇头、探头等表演动作不能同时直接写电机。每个行为声明所占转轴、可打断点、最大时长和结束后的跟随恢复方式。表演期间继续采集图像；需要临时偏离目标时暂停对应轴的跟随，动作结束后先确认目标仍可见，再平滑恢复。只在经过验证的不同转轴上允许并行动作。

**目标与失踪：**用临时 track_id 维持同一个目标，人物左右移动不等于重新挑人；track_id 不代表真实身份。短暂遮挡先停住追随，超过配置时间再小范围找人，找不到回待机。不把画面大小直接当精确距离，不因另一个人一闪而过立即抢走目标。目标丢失、达到机械限位或帧过期时，由确定性控制逻辑降速或停止相应运动。

**接口约定：**感知输出 track_id、目标框或中心、可见性、观测质量、时间戳与帧对应的头部姿态；决策输出 target_id、behavior_id、强度档位和 state_version；行为库提供动作参数及跟随恢复规则；控制桥返回 command_id、执行中/完成/中断/失败和当前姿态。过期决策、未知行为 ID 和重复指令由调度层处理，完成状态以硬件回执为准。停止指令、限位和故障处理不经过模型判定。

技术参考：[ViSP 官方随臂摄像头视觉伺服示例](https://github.com/lagadic/visp/blob/master/example/servo-universal-robots/servoUniversalRobotsIBVS.cpp)。示例说明该类控制方法有实现基础，不代表本项目已完成适配或达到性能目标。

## 3.2 IP 配置与通用系统的接口（架构建议）

**系统机制与内容分离：**感知与硬件控制提供可复用能力；IP 配置声明形态、候选行为、互动条件、成长规则和呈现素材。JEV 读取当前 IP 配置、现场状态与成长记录，输出被允许的行为或形态；同一决策接口可服务不同 IP。

**建议的数据关系：**ip_id 对应 IP；form_id 对应该 IP 树中的节点；model_asset_id 引用节点的角色视觉／3D 模型，与 JEV 决策模型分别管理。节点关联图片、行为配置与允许的后继分支。运行状态保存当前模型引用、形态节点和进化路径；hardware_profile 描述实际硬件能力。

**更换 IP 的边界：**对于现有硬件已支持的能力，更换角色配置和行为内容应能复用感知、调度和控制链路。新增 IP 若需要新的动作、传感器或输出方式，仍需新增并验证相应模块；IP 配置不能凭空增加硬件能力。首轮先以牛来验证模块分离和完整运行链路。

## 3.3 云端网站、本机控制内核与真实硬件（2026-09-23）

**本轮已确认的产品方向：**网站部署在云端，展示一个真实硬件实例及其对应的软件状态；用户进入硬件连接模式后，通过当前电脑驱动机械臂等设备。页面需要说明宠物当前处于哪个等级、已经解锁什么、还可以从哪些方面进化。成长使同一硬件能执行更多已准备好的动作、声音与互动内容。牛来是首个展示 IP，控制内核应保持可复用。

**推荐连接方式：**云端网站 ↔ 云端会话与配对服务 ↔ 电脑上的本机连接程序 ↔ 机械臂、随头摄像头与电脑音箱。本机程序主动建立带身份认证的 WSS 长连接，浏览器通过云端订阅状态并提交高层行为请求。首版不要求用户开放电脑公网端口。该链路是待实现的工程建议，不表示目前已经连通。

云端保存会话记录、IP 配置、成长事件和网站可读取的状态投影；本机运行现场会话状态机、感知、行为调度与硬件适配，负责本轮状态转换和实际执行。网站发出请求，本机检查当前会话、等级、设备能力与控制权限后执行，回执再更新云端与页面。云端与本机不能各自独立升级；首版以本机产生的带序号事件驱动云端投影。网络中断时页面标记状态过期并停止接收远程控制，不重放旧动作；本机按已验证的设备停止策略处理。

**模型与控制边界：**JEV 继续负责在允许的行为集合内选择；Laya 仍是备选本机决策引擎。持续视觉跟随、电机轨迹、动作仲裁、限位与停止留在本机确定性控制逻辑中，不逐帧绕行云端，不等待模型批准。模型输出不能扩大能力白名单。

### 3.3.1 用户怎样连接

1. 点击右上角“连接硬件”（替换 WORK），进入真实硬件状态页；未配对时仍可查看进化路线，但不能触发机械运动。
2. 在要连接的电脑上启动本机连接程序，由程序生成短时、一次性配对码；网站输入配对码，本机确认匹配的网站会话。配对需绑定登录身份、电脑实例与有效期，并限制尝试次数。配对码不是永久访问凭据。
3. 在本机程序中选择机械臂和摄像头，完成所需系统权限与设备初始化。具体 USB、串口、蓝牙或厂商 SDK 路径以设备型号确定；声音首版可使用电脑或外接音箱。
4. 程序回传设备身份、支持的行为、就绪状态和时间戳后，网站显示对应设备。电脑在线不等于机械臂就绪；首次检查先读状态，实际运动另由现场用户触发。
5. 现场用户明确开始本轮控制，程序授予有有效期的单一控制租约。其他页面可观看但不能抢占。断开、租约失效或用户停止时撤销后续指令；重新连接需要重新确认控制，不自动恢复旧动作。

网页入口不提供虚假的“连接成功”、示例配对码或无效下载按钮。本机程序尚未交付时，显示“连接服务尚未接入”及连接步骤。安装本机程序是单独的交付动作，需经 Eric 明确批准。

### 3.3.2 进化与当前状态怎样对应

网站分别显示角色模型与进化状态、设备执行状态。当前可执行能力由当前形态的行为配置、硬件支持、已部署并验证的行为库及就绪条件共同决定。设备掉线不改变当前形态；进入新分支也不凭空增加硬件自由度、负载或运动范围。

| 维度 | 形态与资源的对应 | 页面应说明什么 |
|-|-|-|
| 角色模型 | 每个形态绑定对应的视觉／3D 模型。 | 当前模型与形态、资源就绪状态；模型未加载成功不显示进化已完成。 |
| 动作表达 | 当前节点配置对应动作与组合，不按统一阶段递增。 | 当前可用动作、候选分支差异及硬件是否支持。 |
| 声音与语言 | 各形态绑定相符的台词、音频与节奏。 | 素材是否就绪、由哪个设备播放；切换形态时同步配置。 |
| 进化路径 | 沿当前节点已定义的后继连接评估。 | 当前节点、实际路径、各分支条件；未定义的连接不自行补画。 |
| 硬件扩展 | 新增执行器、传感器或工具需实际适配。 | 独立说明支持状态，不随进化自动宣称获得。 |

网站沿用第 5 节的分支进化树，显示当前角色视觉／3D 模型、对应形态及实际走过的路径。普通牛来已有图和模型；幼年牛来、成熟牛来、硬牛及其他节点的模型准备情况和树中连接分别维护。本轮结束后恢复配置的初始状态，不默认从幼年开始。没有实际会话时显示“尚未开始”；资源预览标记为“形态预览”，与运行中的形态区分，不虚构等级或固定终点。

### 3.3.3 网站状态与执行证据

状态面板同时展示所连接电脑、真实硬件型号与设备标识、机械臂/摄像头/声音通道状态、本轮等级、当前行为与最近回执时间。连接进程至少区分未配对、等待本机确认、电脑在线但设备未就绪、可开始、执行中、已停止、失联及故障，并给出对应的下一步操作。渲染模型是角色展示；实物照片或实时画面尚未接入时不得称为实时硬件画面。

成长与行为共用 session_id、pet_instance_id、ip_id、form_id、hardware_id、bridge_id 和 state_version。行为请求另带唯一 command_id、behavior_id、有效期与控制租约标识；回执区分已接受、执行中、完成、中断、失败与结果未知。“已接受”不等于“已完成”。动作是否完成以设备可提供的回读证据为准；若只确认写入串口，则只能显示已发送。复合回应须收齐本次必需的动作与音频结果才能增加一次有效互动。

事件按会话与事件 ID 去重，状态按递增版本更新，重复回执不重复加经验，晚到结果不能进入新会话。断线时显示最后一次已知状态与时间；超时不能直接宣称失败或完成。重连先获取完整快照、核对未决指令和设备姿态，再允许新操作。网页“停止”需等待本机回执才能显示“已停止”；离线无法确认时提示使用现场停止入口，网页按钮不能替代设备物理急停。

### 3.3.4 实现顺序与验收

第一步把 WORK 整页替换为成长控制台，完成本地资源导入、角色模型预览、形态资源清单、分支配置、演示事件与真实连接空状态；第二步实现本机能力包持久化、配对与设备身份验证；第三步接入一个经过验证的动作与一个音频回应，完成本机执行—硬件回执—页面更新的闭环；最后接入分支进化规则与云端事件补传。具体硬件型号、连接协议与驱动仍待明确。演示动作计数仅用于验证配置，不能充当正式进化条件。

验收需覆盖未安装程序、配对码无效或过期、电脑在线但硬件缺失、正常动作完成、重复请求、拔线、停止、断线重连和上一轮晚到结果。视觉检查覆盖桌面与手机；等级增长必须由实际有效互动产生，不能由点击预览或升级动画产生。

**备选方案：**单台兼容串口设备可以评估浏览器 Web Serial，以减少安装步骤；但它需要安全上下文和用户授权，浏览器覆盖有限，而且不能自然统一摄像头、音频与多种厂商驱动。已有本机服务的项目也可以评估浏览器直连本机；其来源校验、配对、浏览器访问限制与兼容性需要单独验证。本项目首选本机程序主动连云端。参考：[MDN Web Serial API](https://developer.mozilla.org/en-US/docs/Web/API/Web_Serial_API)。

### 3.3.5 本地能力包与成长控制台（本轮补充）

**Eric 本轮明确：**希望模型文件、动作操作文件优先保留在当前电脑，方便现场展示、同步数据，减少服务器负载与网络往返；原 WORK 整页作为软硬件结合的成长控制台，实时展示角色状态与进化。这里沿用第 5 节最新的分支进化树，不恢复旧的线性三级设定。

**本地保存和执行：**角色 GLB、纹理、动作配置、音频与进化配置组成可版本化的 IP 能力包。每个形态关联自己的模型和动作；分支文件声明合法后继与条件。本机保存当前节点、实际路径、执行结果与待同步事件，实时运动与停止由本机处理。目标模型、动作或必要资源缺失时，不执行进化切换；不能只改形态名称而保留旧模型。

**两类模型分开：**角色视觉／3D 模型确定优先放本地。AI 推理模型是否本地运行需按运行后端与设备性能验证；Laya 仍是候选，不将云端 JEV 宣称为已可本地部署。仅把 GLB 放本地不会消除云端决策延迟。若现场要求完整离线，界面、感知、语音、推理及其所有资源都必须在本机就绪。

**云端保留轻量同步：**同步身份与配对、能力包版本摘要、当前形态投影、进化事件、执行摘要及最后更新时间；默认不持续上传原始视频、音频、模型文件或高频关节数据。素材备份和分发可按需设计，不能与状态同步混为一谈。本机是单个现场会话的状态写入者；事件携带 session_id、event_id 与递增序号，恢复网络后补传并去重。云端不独立重复计算升级，旧指令不随重连重放。

**现场展示的推荐落点：**后续由本机程序提供本地界面和能力包读取，现场控制可在电脑内部完成；云端网站用于配对、同步与远程查看。仅有云端网页加本地文件导入，不等于完整离线可用。同机网页直连本机服务的权限、来源校验和配对另行验证；首版云端控制入口仍可通过本机主动 WSS 连接实现。

**界面实现范围：**WORK 入口改为成长控制台，旧的 section=work 地址也进入控制台。页面展示当前角色模型、形态资源清单、配置的进化分支、动作与声音、本地能力包、设备连接状态和实时事件。提供明确区分的本地演示与真实硬件模式。

当前前端支持用户主动选择本地 GLB、动作 JSON、进化 JSON 和音频，在浏览器内读取与演示，不上传这些文件。文件仅在当前页面持有，刷新后需重新导入；这不是已安装的本机资源库，也不代表 AI 推理或机械臂已经运行。动作配置只引用受支持的视觉动作，不执行任意脚本。内置形态清单依据当前文档，具体树中连接尚未定义，因此模板不虚构分支或升级门槛；导入配置后仅按声明的连接与演示条件切换，模型加载成功后才记录切换完成。

正式本机能力包应补充资源哈希、版本、校验、原子切换与回滚；程序重启后恢复事件队列并校验现场设备状态。预计可减少素材传输和云端执行负担，但具体推理速度、设备响应与并发容量须实测，不预先承诺零延迟或完全离线。

# 4. JEV 在产品中的核心作用

JEV 是结构化决策层：接收场景状态与类型化问题，输出 Choice、Score 或 Noul 结果。Choice 与 Score 提供概率分布和 confidence；Noul 返回命题为真的概率，没有独立 confidence 字段。它选择预设行为，不直接承担视觉测量、电机轨迹或硬件保护。接口依据：[Cloudflare JEV 官方接口说明](https://developers.cloudflare.com/ai/models/typesafe/jev/)。

| 原语 | 回答的问题 | 桌面宠物中的候选用途 |
|-|-|-|
| Choice | 从预先定义的选项中选哪一个？ | 选择互动对象、互动模式、行为 ID、设备路径或下一步处理器。 |
| Score | 当前状态处于有序尺度的哪个位置？ | 根据明确量表选择互动积极程度、行为强度档位或优先级。距离与跟踪质量由感知模块测量，电机幅度和速度由控制层限制。 |
| Noul | 某个明确命题为真的概率是多少？ | 判断当前是否适合主动邀约、是否应回应或是否适合切换互动。急停、限位、失联等硬件保护由确定性规则直接执行。 |

三种原语可基于同一份场景快照评估不同问题；独立问题可合并请求。若问题依赖上一问的结果，应分步处理或由程序约束候选项。各类型分别设置阈值与回退，低置信度或超时不触发新的复杂动作；模型不可用时仍保留有效视觉输入下的基础跟随、明确停止和故障保护。

## 4.1 备选方案：Laya 本机决策与实时互动控制

**方案定位。**Laya 作为本黑客松桌面宠物项目的备选决策引擎，后续可探索部署在电脑本机，通过控制桥驱动硬件互动。目前处于方案储备阶段，尚未安装、接入或完成本机性能验证；是否替换 JEV，待实验结果决定。

**模型介绍。**Laya 是开源的非自回归结构化决策模型，采用 Apache-2.0 许可证。它接收文本或 JSON 状态及预先定义的问题，输出 Choice（选项）、Score（有序评分）、Noul（命题概率）等结果，不生成聊天回复或动作代码。官方提供约 421M 参数的英语和 typed-decisions 版本，以及约 322M 参数的多语言版本。中文互动可优先评估多语言版本，实际效果需验证。

**本机部署的价值。**在电脑本地完成语义判断，可减少决策环节对云端网络的依赖，探索更稳定的互动响应时间，并减少向外发送现场状态。当前已确认的实验电脑为 Apple M4、16GB 统一内存，可作为单模型推理验证平台；实际内存、运行后端兼容性和延迟仍需实测。若要求完整离线，视觉感知、语音识别等上游模块也需要本地运行。

**候选运行链路。**摄像头识别与输入解析 → 现场状态 JSON → 本机 Laya 选择互动对象或预设行为 → 调度状态机与行为库 → 控制桥 → 机械臂、头部、灯光或声音反馈。示例：用户说“看我这边”，视觉模块提供人物位置，Laya 根据话语与当前互动状态选择注视行为，再由行为库和控制桥执行。这里的实时控制指及时选择互动行为，电机轨迹、限位、速度约束与急停仍由确定性控制逻辑负责。

**模块化接入。**快速决策层保留统一适配接口：输入为现场状态、候选行为与问题定义；输出为决策值、概率、模型版本、状态时间戳和错误状态。JEV 与 Laya 分别作为云端和本机实现，切换实现时复用视觉模块、行为库和控制桥。两者置信度不能直接共用同一阈值，需分别用项目数据校准。

**能力边界与回退。**本方案采用的 Laya 文本模型不直接读取原始图片或音频，需由感知模块先转换为可用状态。基础模型的零样本效果不能等同于领域微调版本；应先评估，再按需要微调和校准。低置信度、超时或状态过期时，由状态机进入预设待机、保持或安全停止行为；是否调用 JEV 进一步判断属于后续可选策略，不能默认形成云端依赖。

**后续验证。**使用桌面宠物的真实中文指令和现场状态，比较本机 Laya 与 JEV 的行为选择准确率、误触发率，以及从事件发生到硬件开始响应的 p50/p95 延迟。同时检查模型冷启动、持续运行内存、功耗，以及与视觉模块并行运行时的表现。官方 GPU 测速不能直接视为这台 M4 或完整硬件链路的响应时间。

资料来源：[Laya 官方仓库、模型说明与性能限制](https://github.com/NandhaKishorM/laya)；记录日期：2026-09-22。

# 5. 核心交互流程

**主动交互。**系统按照时间间隔或现场事件刷新状态，视觉模块提供人物和设备状态，调度器把状态交给 JEV。JEV 判断是否值得互动、选择对象和行为类型，并给出互动强度或优先级。调度器检查冷却、当前行为和安全条件后，从行为库取出预设行为，再交给控制桥执行。

**被动交互。**用户说话或发送消息后，输入解析模块把事件写入当前状态。JEV 判断请求类型、是否需要机械动作、应该选择哪种预设互动，以及是否需要打断当前行为。系统随后执行预设的头部、机械臂、灯光、声音或其他反馈，不依赖大语言模型生成回答。

**统一执行原则。**视觉跟随与行为决策各自运行，通过同一运动仲裁器控制机械臂。每轮行为执行状态回写后，再判断继续、结束还是恢复跟随。分别记录视觉到朝向、模型判断、决策到动作的延迟，以及误跟踪、误触发、打断和恢复表现；不把模型延迟等同于整机响应时间。

## 5.1 角色模型与树状分支进化

**2026-09-23 已确认：**IP 形态按树状关系发展，每个形态关联对应的角色视觉／3D 模型，当前形态及其表现跟随角色模型状态。通用系统承载模型与节点的关联、进化分支、条件判断及状态转换；各 IP 定义自己的树。撤下此前的线性能力分级，不预设统一阶段数量、固定顺序或最终形态。

| 系统元素 | 定义 | 接口建议 |
|-|-|-|
| 形态节点 | 树中的一种角色形态，每个形态绑定对应的视觉／3D 模型。 | 形态标识、模型资源、图片、互动配置及允许的后继节点。 |
| 角色模型状态 | 当前使用的角色模型及与该形态对应的呈现状态。 | 记录资源标识、版本、加载状态和当前形态；具体动画等字段随素材类型确定。 |
| 进化分支 | 从一个节点到另一个节点的允许转换。 | 分别定义起点、目标、条件和进化表现；树的实际连接由团队填写。 |
| 当前运行状态 | 当前模型、对应形态及实际经过的进化路径。 | 保存当前节点、模型引用、分支历史和互动上下文，不只保存一个数字等级。 |
| JEV 决策 | 根据互动与当前状态评估允许的行为或进化分支。 | JEV 是决策模型；角色视觉／3D 模型是呈现资源，两者分别管理。 |

**分支规则：**进化沿树中已定义的连接进行。兄弟形态不默认存在高低关系，也不默认继承彼此能力。能否回退、重选分支或切换已解锁形态，按 IP 规则定义；调用失败或设备异常不自动退化。

**建议的进化闭环：**读取当前角色模型状态和对应节点 → 获取合法后继分支 → JEV 结合互动证据评估分支条件 → 校验目标角色模型、素材与硬件能力 → 在当前回应结束或可打断点切换 → 新模型、形态与互动配置一致生效 → 保存路径并更新前端。条件未满足时继续当前形态；资源未就绪时不宣告进化成功。

**呈现与状态一致：**每个形态分别关联角色视觉／3D 模型、展示素材与互动内容。进化后不能只改名称而继续展示旧模型。JEV 负责判断，资源管理与状态机负责模型加载和一致切换；不因每形态有一个角色模型就推定需要单独训练一个 JEV。

| 成熟 | 对方询问它不会的能力，或提出未支持的动作 | L2-11：“我先会这些，剩下的慢慢长。” | 歪头，保持关注 | 项目原创 |



保留现有幼年、成熟形态的候选素材及其编号，待与对应角色模型核对；它们不构成固定进化顺序。普通牛来、硬牛和其他形态的内容由团队补充。电影摘录的原片核对与来源说明沿用素材库记录；未核验的归属不视为已验证事实。出场内容按目标形态单独配置。



JEV 每轮参考：当前完整话语、最近几轮对话、当前形态与人设、已解锁候选内容、刚用过的台词与动作、当前参与者及执行状态。选择标准是接得上话、符合人格、台词与动作相容，并减少重复。先由程序限制候选范围，再交给模型选择；首版可把适配好的台词、音频与动作组合成一个行为候选。



可以只做动作、不说话。没有合适台词时，使用当前形态的澄清或回退方式，不调用其他形态专属内容。语音识别失败与语义没有合适答案分别处理，不能把失败算成进化成功。



例如，“你还挺厉害”可能适合得意回应；“我说的是我厉害，不是夸你”则需要结合上一轮收敛，不能再次因“厉害”而昂首。模型选择效果须通过实际中文试聊验证，开放输入不等于能回答所有问题。



### 5.2.4 一轮互动与进化



| 环节 | 观众体验 | 模型 / 前端 / 硬件状态 | 进入下一步的条件 |
|-|-|-|-|
| 开始 | 进入互动位置，自由交流。 | 加载本轮初始角色模型，显示对应形态与参与者。 | 模型、输入与硬件就绪；初始节点待定义。 |
| 当前形态互动 | 与当前牛来交流。 | 按当前形态选择回应，保存真实执行结果。 | 回应完成，更新互动状态；不满足分支条件则继续当前形态。 |
| 评估进化分支 | 互动可能推动不同方向的变化。 | 根据当前模型状态与树中连接，评估合法后继分支。 | 满足具体分支条件；不按固定轮数强制通关。 |
| 转换形态 | 看到对应新模型与表达，并继续互动。 | 目标角色模型、形态、素材与行为配置一致生效，更新路径。 | 目标资源就绪并完成切换；失败保留旧状态。 |
| 结束与复位 | 查看实际到达的形态与路径，让下一位体验。 | 清理会话，恢复配置的初始模型与硬件姿态。 | 界面、模型、执行器均确认就绪；不固定终点文案。 |



进化条件按分支定义，互动记录可作为依据之一；撤下按统一互动轮数逐级通关的建议。只有输入与执行结果可信时才更新相关证据。停止、重复提交、背景话语及识别或执行失败不误记为进化完成。



JEV 评估互动语义与分支条件；状态机依据当前角色模型状态、树中合法连接、证据及执行回执提交转换。不能进入不存在的节点、重复提交转换或仅凭模型声称“完成”就进化。角色模型、形态配置和前端显示须一致。



能否回退、重选分支、重新培养或由工作人员预览，按进化树与展示规则确定。无人回应时可以结束互动，不自动推进到任何形态。



### 5.2.5 现场交互约定



- \*\*每轮关注一位参与者。\*\*开始时通过互动位置和前端选中框确认对象；无法自动确定时由工作人员点击。围观者进入画面不自动抢走目标。暂时遮挡先等待恢复；不能确认原目标时暂停或重新确认，不把别人接入原会话。
- \*\*跟随与表演协调。\*\*等待时持续关注参与者；点头、歪头等表演占用相应运动轴时，跟随让出控制权。表演造成的预期出画不立即判定离场；结束后恢复关注，再确认目标。
- \*\*前端提示何时说话。\*\*显示“可以说话／正在听／牛来在回应／进化中”，不要求照读台词。首版建议按住说话或点击收音，减少嘈杂环境中的误输入；识别重试仍失败时可用自由文字继续。同一轮仍可能混入旁人声音，不能把普通麦克风等同于说话人身份识别。
- \*\*语音和前端是本次展示的必要输出。\*\*声音可由 MacBook 或外接音箱播放，前端在电脑或外接屏上展示；不要求给牛头新增扬声器、灯光或屏幕。没有旁白，角色自己说话；前端可同步字幕。
- \*\*停止与离场优先。\*\*观众明确要求停止时取消后续互动，不用委屈台词挽留。现场提供明确的停止入口；设备故障与物理停止由控制逻辑立即处理，不等待模型批准。
- **本轮状态与复位。**演示按“会话＋IP”隔离上下文，记录当前角色模型、形态节点与经过路径。结束后清理目标和待执行内容，丢弃旧会话晚到的决策；恢复配置的初始模型状态且机械复位完成后，才允许下一位开始。长期成长是否跨会话保留另行定义。

### 5.2.6 首版验收与边界



1. 新观众能自然交流；测试覆盖已配置的不同进化分支，能到达对应节点并呈现与角色模型一致的互动。条件未满足时保持当前形态，不要求走完所有节点。
2. 同一意思换说法仍能合理回应；能处理简单的否定、纠正与上下文指代，不靠关键词播放固定台词。
3. 台词和动作一致，无合适内容时能回退；前端、声音与真实动作共同表达当前阶段。
4. 多人围观和摄像头随动作移动时，不误换参与者；连续至少五轮能正确开始、进化、结束、复位，旧会话内容不进入新会话。

本轮验证进化树、角色模型、形态配置与软硬件呈现的一致性。已有模型与图片不等于已完成接入；播放进化效果也不等于发生在线学习或训练。普通牛来已有图和模型来自用户确认，实际资源与接入状态仍待核对。

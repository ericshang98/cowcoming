# 给模型制作 Agent / 网站接入 Agent 的要求单

> 历史制作基线记录：以下“当前代码”指早期 `0d8ef21`，不代表最新网站状态。新版已具备 HOME 四角色选择和 WORK 两终点模型；维护时先读 `home-model-selection.md`、`assets/work-route-cows/README.md` 与项目现状。模型能力表可继续用于制作，旧页面和通用导入规划不作为现行产品合同。

日期：2026-09-23。目标：让其他 IP、其他形态的 3D 角色可以在 Cowcoming / 牛来网站展示，并复用待机、行走、手势、视线跟随和嘴型预览。

## 1. 依据与适用范围

- 已核对仓库源码基线 `0d8ef21`，并直接解析当前 GLB 的骨骼、动画、材质资源和形态键。
- 已通过已授权的飞书只读接口核对最新产品文档，仍为修订 **106**，与仓库快照修订一致。相关章节为 §3.2（IP / 形态资源）、§3.3.5（本地能力包）、§5（分支进化树）。
- 本次访问 `https://cowcoming.world/` 未成功，未确认线上最新部署与仓库一致；以下“当前实现”均指本仓库，不冒称线上验收。
- 本文是根据现有实现整理的交付约定和待实现建议，不修改飞书原始规格，也不表示通用模型导入器已经完成。

**推荐交付：单文件 glTF 2.0 Binary，即 `.glb`，包含网格、材质、贴图、蒙皮骨骼、动画和嘴型；同时交付可编辑 `.blend` 源文件。**

`.fbx`、`.obj`、`.stl`、`.blend` 可以作为制作输入，但当前网站没有对应加载流程。`.gltf` 是底层加载器可处理的格式，但可能依赖外部 `.bin` 和纹理；本次交付统一使用资源自包含的 `.glb`，减少丢贴图与路径问题。

## 2. 当前代码实际依赖什么

| 项目 | 当前实现 | 对新资产的要求 |
| --- | --- | --- |

| 主角色文件 | `src/scene/niulai.mjs` 的 `NIULAI_ASSET`，目前为 `/models/niulai-mouth.glb` | 新文件使用独立路径，由网站侧接入 |

| 动画 | `idle`、`walking`、`wave`、`bow`，名称区分大小写 | 完整兼容包必须提供这四个 clip |
| 嘴型 | 精确匹配 `MouthOpen`、`MouthWide`、`MouthRound` | 要兼容“试口型”，必须提供这三个 morph target |
| 模型尺寸 | 首页按包围盒高度缩放至 2.4；世界场景缩放至 1.7 | 无须把模型做成固定高度；要有有效非零高度，清除离群几何体 |
| 本地导入 | 当前 `Portfolio.jsx` 仍是旧 WORK 页面，未发现通用 GLB 导入入口 | 不能承诺“拖进去就能用”；接入需修改前端 |

**三档能力要明确区分：**静态 GLB 可以用于展示；有蒙皮和动画才能复用身体动作；还要有正确的头颈骨骼和嘴型才能完整复用交互。缺少能力时应标记或禁用，不能用“GLB 加载成功”代替完整兼容。

当前参考资产 `public/models/niulai-mouth.glb` 实测：2,095,276 字节（约 2 MiB）、21 根蒙皮骨骼、49,828 个三角形、13 个网格、2 张内嵌 PNG；无必需压缩扩展。动画为 `bow` 2.5 秒、`idle` 3 秒、`walking` 1.5 秒、`wave` 3 秒。它的三个嘴型默认权重均为 1，代码加载后会归零；新资产直接导出全零默认值，避免依赖这项补救。

## 3. 给模型制作 Agent 的交付要求

### 3.1 网格、坐标与材质

1. 每个形态交付独立 GLB。默认姿态脚底落地、身体居中；只有头部的角色使用合理的底部锚点，并在说明中注明。
2. **导出后的 glTF 坐标为 Y 向上，角色正面朝 +Z。** Blender 通常采用 Z 向上、角色朝 -Y，开启 glTF 的 +Y Up 转换；以导出后在网站正对相机为最终判断，避免重复旋转 90°。
3. 建议 Blender 使用米制、1 单位 = 1 米。绑定前整理网格与骨架的旋转和缩放；避免负缩放。已有绑定不要直接 Apply Transform，先在副本核对绑定姿态及动画。
4. 网格有正确法线、UV、权重，关节处保留足够的变形拓扑。AI 生成的静态网格通常仍需清理和重拓扑；改后缀不会生成骨骼或动画。
5. 使用可导出的 PBR 材质，优先 Principled BSDF + 图片纹理。程序纹理、复杂节点效果先烘焙；贴图嵌入 GLB。不要依赖 Blender 灯光或合成器才能看清角色。
6. 移除参考地面、相机、灯光、测试物件及远离角色的网格，防止包围盒错误。保留真正属于角色的配件。
7. 第一版交付不压缩的基准 GLB，使用 PNG/JPEG。Draco 已有本地解码路径，但压缩版本仍须另测；不能因为旧文件使用某扩展就假定任意压缩格式都兼容。

### 3.2 骨架约定

完整兼容建议采用以下主链；四肢和尾巴按角色需要增加，不要求每个 IP 都有同样数量的骨骼：

```text
角色骨架对象（名称可为 CharacterRig，不强制叫 Armature）
└─ Root
   └─ Hips
      └─ Spine
         └─ Chest
            └─ Neck
               └─ Head
```

- `Head` 和 `Neck` 是当前跟随接口的关键名称，必须无前缀、无 `.001` 等后缀；不要将普通网格也命名为这两个名字。`Hips` 是当前水平位移纠正的名称。`Root` / `Spine` / `Chest` 是建议结构，代码不强制查找它们。
- 左右四肢可沿用 `Shoulder.L`、`UpperArm.L`、`Forearm.L`、`Hand.L`、`Thigh.L`、`Shin.L`、`Foot.L` 及对应 `.R`。现有牛来无 `ToeBase`，接入主角色不需要额外添加。
- 头、眼睛、角、嘴、配件必须跟随正确骨骼，不能只绑定身体让它们留在原地。硬质角、眼球等可使用单骨权重或骨骼父级；颈部、肩部等柔软连接要有过渡权重。
- 每顶点建议最多 4 个骨骼影响，清理极小权重并归一化；避免无权重顶点。
- 可以用 Rigify、IK 或其他控制架制作，但交付的是可独立播放的变形骨架及烘焙动画，不能要求浏览器执行 Blender 约束或驱动器。
- 不自动复用旧牛的动画到任意新骨架。复用时先在 Blender 重定向，再烘焙到新角色；骨骼重命名本身不等于重定向完成。

### 3.3 动画名称与语义

| 最终 GLB clip 名 | 必须呈现的动作 | 制作建议 |
| --- | --- | --- |
| `idle` | 站立待机 / 轻呼吸 | 约 2–4 秒，无缝循环 |
| `walking` | 原地行走 | 约 1–1.5 秒，无缝循环；世界场景冲刺会加快此 clip |
| `wave` | 招呼 / 挥手或角色等价动作 | 约 1–2.3 秒，单次，结尾可回待机 |
| `bow` | 低头 / 点头致意 | 约 1–2.3 秒，单次，结尾可回待机 |
| `idle2` | 另一种待机 | 可选；不能代替 `idle` |

上述时长是建议，不是解析限制。当前首页可能把手势加速至 2.3 秒内（环境触发为 2.8 秒），应检查加速后的表现。当前 `nod` / `curious` 等行为映射到 `bow`，`greet` / `happy` 等映射到 `wave`；只导出 `nod`、`dance` 等新名称不会自动改变这些映射。

所有水平移动由网站负责。`Root`、骨架对象不得随行走不断向前漂移；骨盆可保留必要的原地周期摆动，但不能承担累计位移。不要依赖首页锁定 `Hips` 来修复资产，世界场景会暴露问题。

### 3.4 嘴型约定

用 Blender **Shape Keys（形态键）**，不是仅加一根 Jaw 骨。可额外保留下颌骨用于制作，但现有网站实际控制的是 morph target 权重。

| Blender 形态键 | 含义 | 网页测试权重 |
| --- | --- | --- |
| `Basis` | 自然闭嘴基准 | 三个目标全为 0；Basis 不作为独立目标导出 |
| `MouthOpen` | 张嘴、有可信口腔 | Open = 1 |
| `MouthWide` | 横向咧嘴修正 | Open = 0.55，Wide = 1 |
| `MouthRound` | 收圆 / O 型修正 | Open = 0.8，Round = 1 |

Wide / Round 按相对 Basis 的修正制作，并测试与 Open 的组合，避免叠加后过度张嘴。嘴型顶点数量和顺序必须一致。上下唇、口腔、牙齿和舌头如有拆网格，要在导出后确认一起正确变化；不强制网格叫 Mouth，代码遍历目标名。

导出默认三个权重为 0。四个身体动作不要包含与网页嘴型控制相冲突的 weights 动画轨道；嘴型预览是无声音的视觉能力，并非自动语音口型同步。

### 3.5 建议预算（新资产目标，不是现有网站硬限制）

- 单角色目标 20k–60k 三角形，骨骼尽量不超过 64 根。
- 贴图优先 1K–2K；GLB 优先控制在 5 MB 以内，超过 10 MB 时说明原因并提供优化版本。
- 材质 / 绘制批次尽量少，建议不超过 8 组；透明材质谨慎使用。
- 记录实际导出后的三角形、骨骼数、贴图尺寸、文件大小和测试设备，不能只报 Blender 视口面数或承诺未经测量的帧率。

## 4. Blender 实际操作顺序

1. **导入并清理。** 导入原始模型，另存 `.blend`；在绑定和制作形态键前完成会改变顶点结构的处理。检查 UV、法线、比例和朝向，移除孤立碎片。
2. **建骨架。** `Shift+A → Armature`，启用 In Front 便于观察。Edit Mode 放置 Root、Hips、躯干、Neck、Head 和四肢骨骼。头骨枢轴放在颈部与头部连接处。使用左右命名和 Symmetrize 建对称肢体。
3. **绑定。** Object Mode 先选网格，再 Shift 选骨架，使骨架为最后选中的活动对象；`Ctrl+P → Armature Deform → With Automatic Weights`。确认网格上有指向正确骨架的 Armature modifier，以及对应的 vertex groups。
4. **修权重。** Pose Mode 测试头颈、肩膀、肘部、膝盖；Weight Paint 修正串动和塌陷。自动权重只是起点。角、眼睛、牙齿等刚性小件宜明确分配权重，不让自动算法随机影响身体。
5. **做嘴型。** 网格 Object Data Properties → Shape Keys，先建立 Basis，再建立三个指定目标。逐个在 Edit Mode 调顶点；回到默认闭嘴，检查第 3.4 节的组合权重。
6. **做动作。** 在 Action Editor 为四个动作分别建 Action，给所需骨骼写关键帧。30 fps 可作为制作基准。循环动画首尾姿态连续；四个动作共享同一绑定姿态。
7. **烘焙控制。** 若用 IK / 约束，按各动作的帧范围烘焙最终骨骼变换（Visual Keying）；在导出副本上验证去掉控制依赖后仍能独立播放。不要破坏可编辑源文件。
8. **导出。** `File → Export → glTF 2.0`，格式选 **glTF Binary (.glb)**。只包含角色和必要骨架，确认材质、UV、Skinning、Shape Keys、Animations 已启用。采用能分别导出各 Action 的模式；不同版本若通过 NLA Tracks 导出，要逐轨命名并检查结果。记录 Blender 版本和导出设置。
9. **核对导出结果。** 最终 GLB 中必须是四个独立动画，精确名为 `idle`、`walking`、`wave`、`bow`；不能仅导出当前活动动作或合并为一条长时间轴。不要盲开 Apply Modifiers 而丢失形态键，先在副本测试。
10. **重新打开验证。** 在新的 Blender 文件导入最终 GLB，复查骨骼、动作和嘴型，然后到项目浏览器测试。原 `.blend` 播放正常不能替代 GLB 和网页验收。

Blender 官方资料：[骨架变形父级与自动权重](https://docs.blender.org/manual/id/4.5/animation/armatures/skinning/parenting.html)、[glTF 导入导出、蒙皮与形态键动画](https://docs.blender.org/manual/id/5.0/addons/import_export/scene_gltf2.html)。菜单随版本变化，最终导出文件的实际内容优先于选项名称。

## 5. 最终交付包

```text
<ip_id>/<form_id>/<version>/
  character.glb          # 自包含、可直接加载的交付文件
  character.blend        # 可编辑骨架、权重、形态键与动作
  preview.png            # 正面预览
  preview.mp4            # 四个动作、头部跟随测试、四种口型演示
  asset-info.json        # 资产清单，格式建议见下文
  README.md              # 制作步骤、版本、导出设置、来源授权、已知问题与测试结果
```

`asset-info.json` **是交接清单建议，当前网站没有读取器，不是已经生效的配置协议**。至少记录：`ip_id`、`form_id`、`version`、模型文件名、SHA-256、Blender 版本、骨骼名列表、clip 名与时长、morph 名、模型朝向、尺寸、三角形数、贴图尺寸、可用能力和缺失能力。提交前将这些字段填为实测值。

不把不同 IP 或形态做成固定三级进化。制作 Agent 只声明资产对应哪个 IP / form；父子关系、初始节点和解锁条件沿用明确的产品配置，不自行补充。

## 6. 给网站接入 Agent 的任务

### 最小接入：先验证一个新角色

1. 将新资产放在独立路径，例如 `public/models/<ip_id>/<form_id>/character.glb`，保留原始参考资产。
2. 在隔离分支把 `NIULAI_ASSET` 指向新路径，验证首页及 World；该改动只是开发验证方式，不是多角色选择器。
3. 按本要求单核对 GLB 内部名称和资源。若新角色使用另一套命名，选择离线重命名 / 重导出，或明确添加映射代码；当前无自动骨架匹配。
4. 若是头部、四足或无手角色，先明确支持的能力和等价动作；不能将不适用的行走或挥手宣称为已支持。
5. 核对原 About 人形分支使用的是独立 `fuch-human-spin.glb`，其行走名为 `walk`、附带 `spin`。主角色 `walking` 合同不要与这个旧分支混淆。

### 通用接入：后续需要实现，本文未实现

- 将资源路径、骨骼、动画、嘴型和能力声明按 `ip_id` / `form_id` 配置，替换当前写死的牛来常量；保留对现有资产的兼容。
- 支持用户主动选择本地 GLB 时，解析、校验、预览成功后才切换。默认在浏览器内处理，不上传文件；如只保留页面内存，要明确刷新后重选。
- 导入前设定合理文件体积和资源预算，拒绝损坏文件、空场景、无有效高度和无法加载的依赖。GLB 扩展名不保证没有外部 URI；本地包应自包含，不能静默请求任意外链。
- 加载中、成功、缺失能力、解析失败都有明确状态；失败保留原角色，可重新选择。禁用不支持的动作和嘴型按钮，不能静默无反应。
- 切换后清理旧模型实例、动画 mixer、材质、纹理及 object URL；共享缓存资源按所有权处理，避免卸载一个角色影响另一实例。不要让旧回调覆盖新角色状态。
- 独立显示形态预览与真实会话状态；资源切换成功不等于完成进化，更不等于机械臂动作完成。

## 7. 验收清单

- [ ] GLB 通过 glTF 结构校验，记录校验工具和结果；所有警告有说明。
- [ ] 重新导入导出的 GLB，材质和贴图完整，无外部绝对路径依赖。
- [ ] 存在实际蒙皮；所有必要网格随骨骼动作，没有飞散、穿插、塌陷或未绑定配件。
- [ ] 四个 clip 名和语义正确；待机 / 行走可循环；动作结束恢复待机；没有根运动漂移。
- [ ] `Head` / `Neck` 跟随测试方向正确。建议合计左右约 ±35°、上下约 ±23° 范围检查；网页实际还会叠加姿态量，最终以控制器实测为准。
- [ ] 闭嘴、张嘴、咧嘴、圆嘴四种状态及中间权重自然；身体动作期间不会抢写嘴型。
- [ ] 首页启动入场、鼠标跟随、拖动、手势、试口型及 World 行走均验证；朝向、脚底高度、尺寸、光照和裁切合理。
- [ ] 桌面与窄屏都检查，记录设备 / 浏览器 / 帧率或卡顿表现；手机首页存在设计上的下半身裁切，启动画面应检查全身入场。
- [ ] 新接入代码执行 `npm test`、`npm run build`；这些通过不替代视觉和实际资源验收。
- [ ] 交付文件、哈希、clip / 骨骼 / morph 清单、演示录像和已知限制齐全。

**交付完成的判定：最终 GLB 在目标网页中按声明的能力运行，并有实测证据；不以“Blender 已绑定”或“文件成功导出”作为结束。** 本要求单本身没有制作新模型、实现通用导入、部署网站或验证硬件。
